# Binary Classification — Complete Beginner Notes

## 1. What Is Binary Classification?

First, understand the word **Binary**.

Binary means TWO.

Therefore, Binary Classification means predicting one category from exactly two possible categories.

For example:

Imagine a computer checking emails.

It has only two possible answers:

1. Spam
2. Not Spam

The computer receives an email and must choose one of these two categories.

This is Binary Classification.

**Simple definition:**

Binary Classification is a supervised machine learning task in which a model predicts one of two possible classes.

## 2. Understand With Simple Examples

Let's look at some everyday examples.

| Problem | Class 1 | Class 2 |
|---|---|---|
| Email detection | Spam | Not Spam |
| Loan prediction | Approved | Rejected |
| Fraud detection | Fraud | Genuine |
| Medical screening | Positive | Negative |
| Customer prediction | Will Buy | Will Not Buy |
| Student result | Pass | Fail |

Notice something important.

Every problem has exactly TWO possible categories.

That is the main idea of Binary Classification.

## 3. Understand Input (X) and Output (Y)

Let's build a simple example.

Imagine we want to predict whether a student will pass or fail.

We collect information about students.

| Study hours (X) | Result (Y) |
|---:|---|
| 1 | Fail |
| 2 | Fail |
| 3 | Fail |
| 5 | Pass |
| 6 | Pass |
| 8 | Pass |

Here:

- X = Study hours.
- Y = Student result.
- Pass and Fail = Two possible classes.

The model studies these examples.

Later, we give it a new student's study hours.

For example:

Study hours = 6

The model predicts:

Pass.

Important: This is a simplified example. Real student performance depends on many other factors too.

## 4. How Does the Model Learn?

Let's understand the process step by step.

**Step 1: Give training examples**

We provide the model with student information and their correct results.

**Step 2: The model studies the examples**

It tries to identify patterns that help distinguish Pass from Fail.

**Step 3: The model receives new information**

For example:

A new student studied for 7 hours.

**Step 4: The model predicts a class**

It predicts Pass.

The important idea:

The model learns from examples where the correct answers are already available.

## 5. What Is a Probability in Binary Classification?

This is an important concept.

A classification model can estimate the probability of a particular class.

Imagine a model predicting whether an email is Spam.

Its output is:

| Class | Probability |
|---|---:|
| Spam | 80% |
| Not Spam | 20% |

The model estimates that the email has an 80% probability of being Spam.

It therefore predicts Spam.

Another example:

| Class | Probability |
|---|---:|
| Spam | 25% |
| Not Spam | 75% |

Now the model predicts Not Spam.

Remember:

Probability is the model's estimate. It does not guarantee that the prediction is correct.

## 6. What Is a Classification Threshold?

A threshold is a decision boundary used to convert a predicted probability into a class.

Let's use a simple example.

Suppose our model predicts the probability of Spam.

We choose a threshold of 50%.

The decision rule is:

- Probability of Spam is 50% or higher → Predict Spam.
- Probability of Spam is below 50% → Predict Not Spam.

Examples:

| Spam probability | Prediction |
|---:|---|
| 90% | Spam |
| 80% | Spam |
| 65% | Spam |
| 50% | Spam |
| 40% | Not Spam |
| 10% | Not Spam |

The threshold controls how easily the model predicts the positive class.

The threshold does not change the model's learned parameters; it changes the decision rule applied to its probability.

## 7. What Are Positive and Negative Classes?

In Binary Classification, we often call the two classes:

- Positive class
- Negative class

Example: Fraud detection.

- Fraud = Positive
- Genuine = Negative

Another example: Spam detection.

- Spam = Positive
- Not Spam = Negative

Important:

Positive does not always mean good.

Negative does not always mean bad.

They are simply names for the two classes.

We decide which category is Positive when setting up the classification problem.

## 8. What Is a Confusion Matrix?

A Confusion Matrix helps us understand the predictions made by a classification model.

Imagine we use a model to identify fraudulent transactions.

There are four possible outcomes.

### 8.1 True Positive (TP)

The transaction is actually Fraud.

The model predicts Fraud.

Both are correct.

### 8.2 True Negative (TN)

The transaction is actually Genuine.

The model predicts Genuine.

Both are correct.

### 8.3 False Positive (FP)

The transaction is actually Genuine.

But the model predicts Fraud.

The model raises a false alarm.

### 8.4 False Negative (FN)

The transaction is actually Fraud.

But the model predicts Genuine.

The model misses a fraudulent transaction.

### Summary

| Actual class | Predicted class | Result |
|---|---|---|
| Fraud | Fraud | True Positive |
| Genuine | Genuine | True Negative |
| Genuine | Fraud | False Positive |
| Fraud | Genuine | False Negative |

Remember these four outcomes. They are essential for understanding classification evaluation.

## 9. Important Evaluation Metrics

After training a Binary Classification model, we need to evaluate its performance.

### 9.1 Accuracy

Accuracy tells us how many predictions were correct out of all predictions.

Example:

- Total transactions: 100
- Correct predictions: 90
- Incorrect predictions: 10

Accuracy = 90%.

### 9.2 Precision

Precision answers:

When the model predicts Fraud, how often is it actually Fraud?

Example:

- Model predicts 20 transactions are Fraud.
- 15 are actually Fraud.

Precision = 15 / 20 = 75%.

### 9.3 Recall

Recall answers:

Out of all actual Fraud transactions, how many did the model identify?

Example:

- Actual Fraud transactions: 100.
- Model identifies 80.

Recall = 80 / 100 = 80%.

### 9.4 F1 Score

F1 Score combines Precision and Recall.

It helps evaluate a model when both are important.

### 9.5 Specificity

Specificity measures how well the model identifies the Negative class.

In our example, it measures how well the model identifies Genuine transactions.
