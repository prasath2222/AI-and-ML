
# Feature Engineering for Regression — Complete Guide

# 1. What Is Feature Engineering?

Imagine you want to predict house prices.

Your dataset contains:

| Size | Bedrooms | Age | Price |
|---:|---:|---:|---:|
| 1000 | 2 | 10 | 20 |
| 1500 | 3 | 8 | 30 |
| 2000 | 3 | 5 | 40 |
| 2500 | 4 | 2 | 50 |

Your model receives three input features:

- Size
- Bedrooms
- Age

But perhaps house price also depends on:
- Size per bedroom.
- How old the house is.
- Whether the house is unusually large.
- How size and age work together.

Your original dataset does not directly contain all these relationships.

You can create additional features using existing information.

This is called **Feature Engineering**.

### Simple definition

Feature Engineering is the process of creating, transforming, or selecting input features to help a Machine Learning model learn useful patterns.

Example:

```python
size = 2000
bedrooms = 4

size_per_bedroom = size / bedrooms

print(size_per_bedroom)

# 500
```

You created a new feature from two existing features.

---

# 2. Why Is Feature Engineering Important?

Imagine two models.

### Model A

```text
Size
Bedrooms
Age
```

### Model B

```text
Size
Bedrooms
Age
Size per bedroom
Age squared
Size squared
Size × Age
```

Model B has additional information represented through engineered features.

This may help it learn relationships that Model A cannot easily represent.

However, more features do not automatically mean better performance.

New features may be:

- Irrelevant.
- Redundant.
- Noisy.
- Highly correlated with existing features.
- Based on information unavailable at prediction time.

Feature Engineering is about creating useful features, not creating as many as possible.

# 3. Mathematical Transformations of Features

A transformation changes how an existing feature is represented.

## 3.1 Squaring a Feature

Suppose your original feature is house size.

```python
size = 2000

size_squared = size * size

print(size_squared)

# 4000000
```

Mathematically:

```text
size_squared = size²
```

Why might this be useful?

A simple linear regression model may struggle when the relationship between house size and price is curved.

Adding `size_squared` allows the model to learn a quadratic relationship.

### Model without squared feature

```text
Prediction = w1 × x + b
```

### Model with squared feature

```text
Prediction = w1 × x + w2 × x² + b
```

The model learns the weights.

IMPORTANT:

This is still Linear Regression because the model is linear in its learned coefficients.

### Python example

```python
size = [1000, 1500, 2000, 2500]

size_squared = []

for value in size:
    size_squared.append(value ** 2)

print(size_squared)
```

Output:

```text
[1000000, 2250000, 4000000, 6250000]
```

## 3.2 Other Mathematical Transformations

You can also create features using:

- Square roots.
- Cubes.
- Logarithms.
- Absolute values.
- Reciprocal values.

Example:

```python
import numpy as np

size = np.array([1000, 1500, 2000, 2500])

size_squared = size ** 2

size_cubed = size ** 3

size_sqrt = np.sqrt(size)

print(size_squared)
print(size_cubed)
print(size_sqrt)
```

Not every transformation is useful.

Choose transformations based on the data and problem.

# 4. Polynomial Features

Polynomial features extend the previous idea.

Instead of creating only a squared feature, you can create features with different powers.

Original feature:

```text
Size
```

Polynomial features:

```text
Size
Size²
Size³
```

### Degree 1

```text
Prediction = w1 × x + b
```

Ordinary Linear Regression.

### Degree 2

```text
Prediction = w1 × x + w2 × x² + b
```

Can represent a quadratic relationship.

### Degree 3

```text
Prediction = w1 × x + w2 × x² + w3 × x³ + b
```

Can represent more complex curves.

### Python example

```python
import numpy as np

from sklearn.preprocessing import PolynomialFeatures

X = np.array([
    [1000],
    [1500],
    [2000],
    [2500]
])

poly = PolynomialFeatures(
    degree=2,
    include_bias=False
)

X_poly = poly.fit_transform(X)

print(X_poly)
```

Conceptually, the generated columns are:

```text
Size       Size²
1000       1000000
1500       2250000
2000       4000000
2500       6250000
```

### Important: Polynomial degree

Higher degrees can represent more complicated patterns.

But they can also create overfitting.

For example:

- Degree 1 may be too simple.
- Degree 2 may capture a useful curve.
- Degree 10 may fit training observations closely but perform poorly on unseen data.

Compare different degrees using validation data.

Do not assume higher degree is always better.

# 5. Interaction Features

An interaction feature represents the combined effect of two or more input features.

Imagine house price depends on:

- Size.
- Age.

Perhaps the relationship between size and price changes depending on how old the house is.

You can create an interaction feature by multiplying the two features.

```python
size = 2000
age = 10

size_age = size * age

print(size_age)

# 20000
```

Mathematically:

```text
size_age = size × age
```

### Model without interaction

```text
Prediction = w1 × size + w2 × age + b
```

### Model with interaction

```text
Prediction =
w1 × size
+ w2 × age
+ w3 × (size × age)
+ b
```

The additional interaction term allows the relationship between size and price to depend on age.

### Python example

```python
size = [1000, 1500, 2000, 2500]

age = [10, 8, 5, 2]

size_age = []

for s, a in zip(size, age):
    size_age.append(s * a)

print(size_age)
```

Output:

```text
[10000, 12000, 10000, 5000]
```

### More interaction examples

| Original features | New interaction feature |
|---|---|
| Size × Age | Size_Age |
| Size × Bedrooms | Size_Bedrooms |
| Income × Experience | Income_Experience |
| Price × Quantity | Total_Value |

Interaction features should have a meaningful reason.

Do not multiply every possible pair of features without considering the problem.

# 6. Ratio Features

A ratio feature is created by dividing one feature by another.

Example:

```python
size = 2000

bedrooms = 4

size_per_bedroom = size / bedrooms

print(size_per_bedroom)

# 500
```

This feature represents average house size per bedroom.

### Why might this help?

Consider two houses:

| House | Size | Bedrooms | Size per bedroom |
|---|---:|---:|---:|
| A | 2000 | 4 | 500 |
| B | 2000 | 2 | 1000 |

Both houses have the same total size.

But the size available per bedroom is different.

The ratio gives the model another way to represent the structure of the house.

### Python example

```python
size = [1000, 1500, 2000, 2500]

bedrooms = [2, 3, 3, 4]

size_per_bedroom = []

for s, b in zip(size, bedrooms):

    if b != 0:
        size_per_bedroom.append(s / b)

    else:
        size_per_bedroom.append(None)

print(size_per_bedroom)
```

IMPORTANT:

Division by zero is not allowed.

Always consider zero values and missing values when creating ratio features.

A ratio is not automatically useful. Test whether it improves validation performance.

# 7. Log Transformation

Sometimes a feature contains very large values or has a strongly right-skewed distribution.

A logarithmic transformation can reduce the range of large values.

Example:

```python
import numpy as np

size = [1000, 2000, 5000, 10000, 50000]

log_size = np.log1p(size)

print(log_size)
```

`np.log1p(x)` calculates:

```text
log(1 + x)
```

It is useful when values can include zero because it avoids calculating the logarithm of zero.

### Why use a log transformation?

Imagine:

```text
1000
2000
5000
10000
50000
```

The difference between 10,000 and 50,000 is much larger than the difference between 1,000 and 2,000.

A log transformation compresses large values.

This can help some models represent relationships more effectively.

### Important

A log transformation does not guarantee better performance.

Also, if you transform the target variable, you must carefully reverse the transformation when interpreting predictions.

Example:

```python
predicted_price = np.expm1(predicted_log_price)
```

This converts a prediction made on the `log1p` scale back to the original price scale.

# 8. Date and Time Features

Dates can contain useful information.

Imagine you are predicting monthly house sales.

Your dataset contains:

```text
Date
Sales
```

The date itself may not be directly useful to a basic regression model.

You can extract information from it.

Examples:

- Year.
- Month.
- Day.
- Day of week.
- Quarter.
- Weekend indicator.

### Python example

```python
import pandas as pd

df = pd.DataFrame({
    "date": [
        "2026-01-15",
        "2026-02-20",
        "2026-03-10"
    ]
})

df["date"] = pd.to_datetime(df["date"])

df["year"] = df["date"].dt.year

df["month"] = df["date"].dt.month

df["day"] = df["date"].dt.day

df["day_of_week"] = df["date"].dt.dayofweek

print(df)
```

These new columns represent different parts of the date.

## 8.1 Cyclical Features

Months have a special property.

December and January are next to each other in the calendar.

But numerically:

```text
December = 12

January = 1
```

A model using ordinary numerical values may not understand that these months are adjacent.

One solution is to create cyclical features using sine and cosine.

For month m:

```text
month_sin = sin(2 × π × m / 12)

month_cos = cos(2 × π × m / 12)
```

Python:

```python
import numpy as np

month = 12

month_sin = np.sin(2 * np.pi * month / 12)

month_cos = np.cos(2 * np.pi * month / 12)

print(month_sin)
print(month_cos)
```

These features represent the circular nature of the calendar.

This is useful in seasonal prediction problems.

The same idea can be applied to:

- Hours of the day.
- Days of the week.
- Months.
- Other repeating cycles.

# 9. Feature Creation Using Domain Knowledge

Domain knowledge means understanding the real-world problem you are solving.

You can use that knowledge to create meaningful features.

For house-price prediction:

| Original features | Possible engineered feature |
|---|---|
| Size, Bedrooms | Size per bedroom |
| Construction year | House age |
| Land area, Building area | Land-to-building ratio |
| Location | Location category or geographic features |
| Bathrooms, Bedrooms | Bathrooms per bedroom |

Example:

```python
construction_year = 2010

current_year = 2026

house_age = current_year - construction_year

print(house_age)

# 16
```

Instead of using construction year directly, you create a feature representing the house's age.

IMPORTANT:

For real-world prediction, use the date at which the prediction is being made.

Do not calculate house age using a future date that would not be available at prediction time.

Domain knowledge helps you create useful features, but you must test whether they actually improve the model.

# 10. Feature Selection

Feature Engineering creates or transforms features.

Feature Selection chooses which features should be used by the model.

Imagine your dataset contains:

```text
Size
Bedrooms
Age
Location
Size_squared
Size_per_bedroom
Size_age
Random_ID
Duplicate_feature
Price
```

Not every column is useful.

For example:

- Random_ID may contain no useful information.
- Duplicate_feature may repeat another feature.
- Some engineered features may add noise.
- Some features may be strongly related to the target.

Feature Selection helps identify a useful set of input features.

### Why does Feature Selection matter?

Too many unnecessary features can:

- Increase training complexity.
- Increase memory usage.
- Make the model harder to interpret.
- Increase overfitting risk in some settings.
- Introduce redundant information.

However, removing useful features can make the model worse.

Feature selection should be based on evidence, not guesswork.

---

# 11. Feature Selection Methods

There are three major categories.

## 11.1 Filter Methods

Filter methods evaluate features using statistical measures before training a particular model.

Examples:

- Correlation.
- Mutual information.
- Variance threshold.
- Statistical tests.

### Example: Correlation

```python
import pandas as pd

data = {
    "size": [1000, 1500, 2000, 2500],
    "bedrooms": [2, 3, 3, 4],
    "age": [10, 8, 5, 2],
    "price": [20, 30, 40, 50]
}

df = pd.DataFrame(data)

correlation = df.corr(numeric_only=True)

print(correlation["price"])
```

Correlation measures how strongly two variables move together in a linear way.

A high correlation does not prove that one feature causes the target to change.

A low correlation does not prove that a feature is useless. It might have a nonlinear or interaction-based relationship with the target.

## 11.2 Wrapper Methods

Wrapper methods evaluate different feature subsets by training and evaluating a model.

Example:

1. Train using all features.
2. Train using a smaller feature subset.
3. Compare validation performance.
4. Keep the subset that performs better.

One common method is Recursive Feature Elimination (RFE).

### Python example

```python
from sklearn.feature_selection import RFE

from sklearn.linear_model import LinearRegression

model = LinearRegression()

selector = RFE(
    estimator=model,
    n_features_to_select=2
)

selector.fit(X_train, y_train)

print(selector.support_)

print(selector.ranking_)
```

`support_` identifies the selected features.

`ranking_` gives the feature rankings assigned by RFE.

Feature selection should be performed inside the training process, not using the test set.

## 11.3 Embedded Methods

Embedded methods perform feature selection as part of model training.

Examples:

- Lasso Regression.
- Decision Tree feature importance.
- Random Forest feature importance.

### Lasso example

```python
from sklearn.linear_model import Lasso

model = Lasso(alpha=0.1)

model.fit(X_train, y_train)

print(model.coef_)
```

Lasso uses L1 regularization.

It can make some coefficients exactly zero.

A coefficient of zero means that the feature does not contribute through that fitted coefficient.

IMPORTANT:

With highly correlated features, Lasso may select one feature and discard another similar feature.

The selected feature is not necessarily the only meaningful one.

# 12. Polynomial Features vs Interaction Features

These concepts are related but different.

| Polynomial features | Interaction features |
|---|---|
| Use powers of features | Combine different features |
| Example: size² | Example: size × age |
| Can represent curved relationships | Can represent combined effects |

For example:

Original features:

```text
Size
Age
```

Polynomial expansion of degree 2 can create:

```text
Size
Age
Size²
Size × Age
Age²
```

Notice that polynomial expansion can create both squared features and interaction features.

### Python example

```python
import numpy as np

from sklearn.preprocessing import PolynomialFeatures

X = np.array([
    [1000, 10],
    [1500, 8],
    [2000, 5],
    [2500, 2]
])

poly = PolynomialFeatures(
    degree=2,
    include_bias=False
)

X_poly = poly.fit_transform(X)

print(
    poly.get_feature_names_out(["size", "age"])
)

print(X_poly)
```

The generated feature names include:

```text
size
age
size^2
size age
age^2
```

Be careful with high polynomial degrees because the number of generated features can grow quickly.

# 13. Feature Engineering and Overfitting

Creating additional features can improve a model.

But it can also cause overfitting.

Imagine:

### Model A

```text
Size
Bedrooms
Age
```

### Model B

```text
Size
Bedrooms
Age
Size²
Age²
Size³
Age³
Size × Age
Size × Bedrooms
Age × Bedrooms
```

Model B is more flexible.

It may fit the training data better.

But it might also learn random patterns that do not generalize to new houses.

### Example

| Model | Training RMSE | Validation RMSE |
|---|---:|---:|
| Model A | 5.0 | 5.5 |
| Model B | 1.0 | 9.0 |

Model B has much lower training error.

But its validation error is much higher.

This suggests that Model B may be overfitting.

The objective is not to achieve the lowest training error.

The objective is to learn patterns that work well on unseen data.

# 14. Feature Engineering Without Data Leakage

This is extremely important.

Suppose you want to create a new feature using the average house price in a particular location.

### Incorrect approach

Calculate the location's average price using the entire dataset, including test rows.

Then use that value as a feature.

This can leak target information from the test set.

Target-based feature engineering requires special care.

The same problem can occur with:

- Target encoding.
- Group averages calculated using future observations.
- Features built using information that becomes available only after prediction time.

### Safe approach

1. Split your data.
2. Learn feature-generation parameters from training data only.
3. Apply the learned transformation to validation and test data.
4. Ensure that every feature would genuinely be available at prediction time.

For more complex target-based transformations, use cross-validation-based or out-of-fold methods.

For time-series data, also preserve chronological order.

# 15. A Practical Feature Engineering Pipeline

Here is a small example using the house-price problem.

```python
import pandas as pd

data = {
    "size": [1000, 1500, 2000, 2500, 3000],
    "bedrooms": [2, 3, 3, 4, 5],
    "age": [10, 8, 5, 2, 1],
    "price": [20, 30, 40, 50, 60]
}

df = pd.DataFrame(data)


# Feature 1: Size per bedroom

df["size_per_bedroom"] = (
    df["size"] / df["bedrooms"]
)


# Feature 2: Squared size

df["size_squared"] = df["size"] ** 2


# Feature 3: Squared age

df["age_squared"] = df["age"] ** 2


# Feature 4: Size-age interaction

df["size_age"] = df["size"] * df["age"]


print(df)
```

You now have:

Original features:

```text
size
bedrooms
age
```

New features:

```text
size_per_bedroom
size_squared
age_squared
size_age
```

Target:

```text
price
```

Next, compare a model trained with the original features against a model trained with selected engineered features.

Use the same training and validation split for a fair comparison.

Do not assume all four new features should be retained.

# 16. Complete Feature Engineering Workflow

A practical workflow:

1. Understand what each original feature represents.
2. Understand the real-world problem.
3. Identify possible missing relationships.
4. Create meaningful new features.
5. Consider polynomial features.
6. Consider interaction features.
7. Consider ratio features.
8. Consider suitable mathematical transformations.
9. Extract useful information from dates when relevant.
10. Investigate redundant or irrelevant features.
11. Select features using training data.
12. Train the model.
13. Compare validation performance.
14. Investigate overfitting.
15. Keep the features that improve generalization or provide useful interpretation.

# 18. Final Understanding

A Machine Learning model learns from the features you provide.

Feature Engineering helps represent useful relationships that may not be obvious in the original dataset.

For example, a house-price model may benefit from:

- House size.
- House age.
- Size per bedroom.
- Squared size.
- Size-age interaction.

But every new feature must have a reason.

The important skill is not creating hundreds of features.

It is understanding the problem, creating meaningful representations, and checking whether they improve performance on unseen data.
