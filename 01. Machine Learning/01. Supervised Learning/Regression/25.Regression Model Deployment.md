
# Regression Model Deployment

## 1. What Is Model Deployment?

Imagine you have trained a house-price prediction model.

Your model has learned:

- Weight for house size
- Weight for number of bedrooms
- Weight for house age
- Bias

After training, the model can predict house prices.

For example:

    House size = 2000
    Bedrooms = 3
    Age = 5

    Model prediction = ₹50 lakh

But there is a problem.

When you close Python, your variables and trained model may disappear.

Do you need to train the model again every time you want to make a prediction?

No.

We can **save the trained model** and load it whenever we need it.

This is one of the main ideas behind model deployment.

---

## 2. Understand the Deployment Process

A typical machine-learning deployment workflow looks like this:

    1. Collect training data
              |
              v
    2. Train the model
              |
              v
    3. Evaluate the model
              |
              v
    4. Save the trained model
              |
              v
    5. Load the saved model
              |
              v
    6. Give it new input data
              |
              v
    7. Generate predictions
              |
              v
    8. Show predictions to users

The important point:

**Training and prediction are two different activities.**

Training teaches the model.

Prediction uses what the model has already learned.

---

## 3. Training a Regression Model

Let's use a house-price dataset.

    import numpy as np

    from sklearn.linear_model import LinearRegression

    # Input features
    X = np.array([
        [1000, 2, 10],
        [1500, 3, 8],
        [2000, 3, 5],
        [2500, 4, 2]
    ])

    # Actual house prices
    y = np.array([20, 30, 40, 50])

Here:

- First column = house size.
- Second column = bedrooms.
- Third column = house age.
- `y` = actual house prices.

Now train the model:

    model = LinearRegression()

    model.fit(X, y)

What happens when we call:

    model.fit(X, y)

The algorithm learns the relationship between the input features and the target.

After training, the model has learned coefficients and an intercept.

We can inspect them:

    print(model.coef_)

    print(model.intercept_)

- `model.coef_` contains the learned feature coefficients.
- `model.intercept_` contains the learned bias.

---

## 4. Make a Prediction Before Saving

Let's predict the price of a new house.

    new_house = np.array([
        [3000, 4, 3]
    ])

    prediction = model.predict(new_house)

    print(prediction)

The model uses its learned coefficients and intercept to calculate a prediction.

Notice that we did not train the model again.

We simply used the already-trained model.

---

## 5. Save the Trained Model

Scikit-learn models can be saved using Python's `joblib` library.

First, import joblib:

    import joblib

Now save the model:

    joblib.dump(
        model,
        "house_price_model.pkl"
    )

This creates a file:

    house_price_model.pkl

That file contains the saved model object, including its learned parameters.

You can now close your Python program.

The saved model file remains available.

---

## 6. Load the Saved Model

Imagine you open Python tomorrow.

You do not need to train the model again.

Load the saved model:

    import joblib

    model = joblib.load(
        "house_price_model.pkl"
    )

Now the variable `model` contains the loaded trained model.

You can inspect its learned parameters:

    print(model.coef_)

    print(model.intercept_)

They represent the parameters learned during the original training.

---

## 7. Make Predictions Using the Loaded Model

Let's provide new house information.

    new_house = np.array([
        [3500, 4, 2]
    ])

    prediction = model.predict(new_house)

    print("Predicted house price:", prediction)

The loaded model can generate predictions without repeating training.

This is the basic idea of saving and reusing a trained model.

---

## 8. Why Must We Save Preprocessing Too?

This is extremely important.

Imagine that your original training data contained house sizes ranging from 1,000 to 5,000.

Before training, you used StandardScaler to scale the features.

Example:

    from sklearn.preprocessing import StandardScaler

    scaler = StandardScaler()

    X_scaled = scaler.fit_transform(X)

Then you trained your model using:

    model.fit(X_scaled, y)

Now the model expects scaled input data.

What happens if you give it the original, unscaled house size?

The model receives data in a format different from the one it learned during training.

Its predictions may become incorrect.

Therefore, we must save the preprocessing transformation along with the model.

There are two main approaches.

### Approach A: Save the scaler and model separately

    import joblib

    joblib.dump(
        scaler,
        "house_scaler.pkl"
    )

    joblib.dump(
        model,
        "house_model.pkl"
    )

When making predictions:

    scaler = joblib.load("house_scaler.pkl")

    model = joblib.load("house_model.pkl")

    new_house_scaled = scaler.transform(new_house)

    prediction = model.predict(new_house_scaled)

The same scaler fitted during training must be used for new data.

Do not fit a new scaler on each prediction request.

### Approach B: Save the complete Pipeline

A Pipeline combines preprocessing and the model into one object.

This is usually easier and safer.

    from sklearn.pipeline import Pipeline

    from sklearn.impute import SimpleImputer

    from sklearn.preprocessing import StandardScaler

    from sklearn.linear_model import LinearRegression

    pipeline = Pipeline([
        ("imputer", SimpleImputer(strategy="median")),

        ("scaler", StandardScaler()),

        ("model", LinearRegression())
    ])

Train the complete pipeline:

    pipeline.fit(X, y)

Save it:

    joblib.dump(
        pipeline,
        "house_price_pipeline.pkl"
    )

Load it:

    loaded_pipeline = joblib.load(
        "house_price_pipeline.pkl"
    )

Predict:

    prediction = loaded_pipeline.predict(new_house)

The pipeline automatically performs:

    New input
        |
        v
    Missing-value imputation
        |
        v
    Feature scaling
        |
        v
    Trained regression model
        |
        v
    Prediction

You do not need to manually call the imputer and scaler.

The pipeline preserves the preprocessing steps and their learned settings.

## 9. Build a Complete Training Script

In a real project, training code and prediction code are often separated.

Example training script:

**train_model.py**

    import numpy as np
    import joblib

    from sklearn.pipeline import Pipeline

    from sklearn.impute import SimpleImputer

    from sklearn.preprocessing import StandardScaler

    from sklearn.linear_model import Ridge

    # Training dataset
    X = np.array([
        [1000, 2, 10],
        [1500, 3, 8],
        [2000, 3, 5],
        [2500, 4, 2]
    ])

    y = np.array([20, 30, 40, 50])

    # Create pipeline
    pipeline = Pipeline([
        ("imputer", SimpleImputer(strategy="median")),

        ("scaler", StandardScaler()),

        ("model", Ridge(alpha=1.0))
    ])

    # Train
    pipeline.fit(X, y)

    # Save
    joblib.dump(
        pipeline,
        "house_price_pipeline.pkl"
    )

    print("Model trained and saved successfully.")

Run this script when you want to train or retrain the model.

---

## 10. Build a Separate Prediction Script

Now create another file.

**predict.py**

    import numpy as np
    import joblib

    # Load trained pipeline
    model = joblib.load(
        "house_price_pipeline.pkl"
    )

    # New house information
    new_house = np.array([
        [3000, 4, 3]
    ])

    # Predict
    prediction = model.predict(new_house)

    print("Predicted house price:", prediction[0])

This script does not contain training code.

It only:

1. Loads the saved model.
2. Receives new input.
3. Generates a prediction.
4. Displays the result.

This separation is useful in real applications.

## 11. What Is a Prediction API?

So far, we have made predictions using Python scripts.

But imagine that you want to build a website.

A user enters:

    House size: 3000
    Bedrooms: 4
    Age: 3

Then clicks:

    Predict House Price

How can the website communicate with your trained Python model?

One common approach is an API.

An API allows another application to send input to your model and receive a prediction.

The process:

    User
      |
      v
    Website
      |
      v
    API request
      |
      v
    Python prediction service
      |
      v
    Saved ML model
      |
      v
    Prediction
      |
      v
    API response
      |
      v
    Website displays result

---

## 12. Create a Simple Prediction API Using FastAPI

FastAPI is a Python framework used to create APIs.

Install the required packages:

    pip install fastapi uvicorn joblib scikit-learn numpy

Create a file:

**app.py**

    import joblib

    import numpy as np

    from fastapi import FastAPI

    from pydantic import BaseModel

    # Create API application
    app = FastAPI()

    # Load trained model
    model = joblib.load(
        "house_price_pipeline.pkl"
    )

    # Define input structure
    class HouseData(BaseModel):

        size: float

        bedrooms: float

        age: float

    # Create prediction endpoint
    @app.post("/predict")

    def predict_house_price(data: HouseData):

        input_data = np.array([[
            data.size,
            data.bedrooms,
            data.age
        ]])

        prediction = model.predict(input_data)

        return {
            "predicted_price": float(prediction[0])
        }

### Understand the important parts

`app = FastAPI()`

Creates the API application.

`@app.post("/predict")`

Creates an API endpoint that accepts POST requests at `/predict`.

`HouseData`

Defines the input fields that the API expects.

`model.predict(input_data)`

Uses the saved model to generate a prediction.

`return`

Sends the prediction back as a response.

### Start the API

Run:

    uvicorn app:app --reload

The API starts on your local computer.

Open the interactive API documentation at:

    http://127.0.0.1:8000/docs

You can test the prediction endpoint using the documentation page.

Example request:

    {
        "size": 3000,
        "bedrooms": 4,
        "age": 3
    }

Example response:

    {
        "predicted_price": 45.6
    }

The response value above is only illustrative.

The actual result depends on the trained model.

## 13. What Is Model Monitoring?

Deployment does not mean that our work is finished.

A deployed model can become less reliable over time.

For example:

Imagine that your house-price model was trained using data from 2024.

By 2028:

- House prices may have changed.
- New neighborhoods may have developed.
- Interest rates may have changed.
- Buyer behavior may have changed.

The relationship between the input features and house prices may no longer be the same.

This problem is related to **model drift**.

Two important concepts:

### Data Drift

The distribution of input data changes.

Example:

The average house size in new incoming data becomes much larger than the average size in the training data.

### Concept Drift

The relationship between input features and the target changes.

Example:

A particular house size used to correspond to a certain price range, but the market changes and the same house size now corresponds to a different price range.

Monitoring helps identify when model performance or input data changes.

Possible monitoring activities:

- Monitor incoming feature distributions.
- Track prediction distributions.
- Collect actual outcomes when they become available.
- Calculate performance metrics.
- Check for missing or invalid inputs.
- Retrain when justified by evidence.

Do not automatically retrain just because time has passed. First examine the data and performance.

## 14. Important Deployment Safety Considerations

### A. Validate Input Data

A prediction API should not blindly accept every input.

Check:

- Required fields exist.
- Values are numeric.
- Values are within reasonable ranges.
- Missing values are handled correctly.

### B. Keep Training and Prediction Features Consistent

The model was trained with:

    [size, bedrooms, age]

Do not accidentally send:

    [age, size, bedrooms]

Feature order matters when using an ordinary numerical array.

### C. Save the Model Version

Keep track of:

- Model version.
- Training date.
- Dataset version.
- Feature names and order.
- Preprocessing configuration.
- Evaluation metrics.

### D. Protect Saved Model Files

Python pickle-based formats, including joblib files, can execute code when loaded.

Only load model files from trusted sources.

Do not load an untrusted `.pkl` or `.joblib` file.

### E. Keep Dependencies Compatible

A model saved using one version of scikit-learn may not work reliably with a different version.

Record the Python and library versions used to train the model.

    Training dataset
          |
          v
    Preprocessing
          |
          v
    Model training
          |
          v
    Model evaluation
          |

          |

          |

Remember these differences:

| Term | Meaning |
|---|---|
| Training | Teaching the model using data |
| Prediction | Using a trained model to generate an output |
| Serialization | Saving a Python object to a file |
| Loading | Restoring a saved object |
| Pipeline | Combining preprocessing and a model |
| API | Allowing another application to communicate with the model |
| Deployment | Making the model available for real use |
| Monitoring | Checking the model's behavior after deployment |
| Data drift | Changes in incoming input data |
| Concept drift | Changes in the relationship between inputs and target |

**The central idea: Train once, save the complete model pipeline, load it when needed, and use it to make predictions on new data.**
