
# Regression Model Selection and Hyperparameter Tuning

## 1. What Is Model Selection?

Imagine you have a house-price prediction dataset.

You want to predict house prices using:

- Size
- Bedrooms
- Age
- Location

You have already prepared your dataset.

Now you need to decide which regression algorithm to use.

Possible choices:

1. Linear Regression
2. Ridge Regression
3. Lasso Regression
4. Elastic Net
5. Polynomial Regression
6. Decision Tree Regression
7. Random Forest Regression
8. Gradient Boosting Regression
9. XGBoost
10. LightGBM
11. CatBoost

Which one should you choose?

You cannot automatically know which algorithm will perform best.

Different algorithms learn relationships differently.

**Model selection** means comparing suitable machine learning models and choosing one based on their performance and other project requirements.

### Example

Imagine you train three models:

| Model | Training RMSE | Validation RMSE |
|---|---:|---:|
| Linear Regression | 8 | 9 |
| Ridge Regression | 8.5 | 8 |
| Random Forest | 2 | 6 |

Which model is better?

If we look only at training RMSE, Random Forest looks best.

But validation RMSE tells us how well the models perform on data they did not use for fitting.

In this example:

- Linear Regression: validation RMSE = 9.
- Ridge Regression: validation RMSE = 8.
- Random Forest: validation RMSE = 6.

Random Forest performs best on the validation data.

These numbers are illustrative.

The important lesson is:

**Choose models using appropriate validation performance, not training performance alone.**

# 2. Understanding Different Regression Algorithms

Before selecting a model, you should understand what each algorithm is useful for.

## 2.1 Linear Regression

Linear Regression tries to represent the relationship between input features and the target using a linear combination of coefficients.

Example:

```python
prediction = (
    w1 * size +
    w2 * bedrooms +
    w3 * age +
    b
)
```

Useful when:

- Relationships are reasonably represented by a linear model.
- You want a simple baseline.
- You need interpretable coefficients.

Limitations:

- May struggle with complex nonlinear relationships.
- Can be affected by outliers.
- Can have unstable coefficients when features are strongly correlated.

## 2.2 Ridge Regression

Ridge is linear regression with L2 regularization.

Useful when:

- You have many features.
- Features contain overlapping information.
- You want to reduce coefficient sizes.
- You want to control overfitting.

## 2.3 Lasso Regression

Lasso uses L1 regularization.

Useful when:

- You want a simpler model.
- Some coefficients may be unnecessary.
- You want regularization that can set coefficients to zero.

## 2.4 Elastic Net

Elastic Net combines L1 and L2 regularization.

Useful when:

- You have many features.
- Some features are strongly correlated.
- You want both coefficient shrinkage and possible feature selection.

## 2.5 Decision Tree Regression

A Decision Tree learns rules by splitting the dataset into smaller groups.

Imagine rules such as:

```text
Is house size less than 1500?

    YES:
        Predict a lower price.

    NO:
        Is house size less than 2500?

            YES:
                Predict a medium price.

            NO:
                Predict a higher price.
```

This is only a simplified illustration.

Decision trees can learn nonlinear relationships and feature interactions without manually creating polynomial features.

Useful when:

- Relationships are nonlinear.
- You want rule-based predictions.
- Feature scaling is not desirable or necessary.

Limitations:

- A deep tree can overfit.
- Small data changes can produce different trees.
- A single tree may have unstable predictions.

## 2.6 Random Forest Regression

Random Forest combines predictions from many decision trees.

Each tree is trained using a randomized sample of the training data and feature-selection process.

For regression, the predictions are generally averaged.

Example:

```text
Tree 1 predicts: 40

Tree 2 predicts: 45

Tree 3 predicts: 43

Random Forest prediction:

(40 + 45 + 43) / 3

= 42.67
```

Useful when:

- Relationships are nonlinear.
- Feature interactions are important.
- You want a strong tree-based baseline.

Limitations:

- Can require more memory and computation.
- Can be less interpretable than a simple linear model.
- Does not always extrapolate well beyond the training target range.

## 2.7 Gradient Boosting Regression

Gradient Boosting builds trees sequentially.

Each new tree attempts to improve the errors made by the existing ensemble.

Simplified explanation:

1. Train an initial model.
2. Measure its errors.
3. Train another tree to improve the predictions.
4. Repeat the process.
5. Combine the contributions of the trees.

Useful when:

- You have structured tabular data.
- Nonlinear relationships exist.
- You want a powerful predictive model.

Examples of implementations include:

- Scikit-learn Gradient Boosting.
- XGBoost.
- LightGBM.
- CatBoost.

These implementations have different algorithms and features; they are not all identical.

# 3. How Do You Compare Models Fairly?

Imagine comparing Linear Regression and Random Forest.

You should not:

- Train Linear Regression on one dataset split.
- Train Random Forest on a completely different split.
- Compare their scores as if the experiment were identical.

Instead, use the same training and validation data.

### Example workflow

```text
Original dataset
       |
       v
Train / Validation / Test split
       |
       +---------------------+
       |                     |
       v                     v
Linear Regression       Random Forest
       |                     |
       v                     v
Train using same        Train using same
training data           training data
       |                     |
       v                     v
Predict validation data
       |                     |
       v                     v
Calculate RMSE for both
       |                     |
       +----------+----------+
                  |
                  v
          Compare performance
```

You should also use appropriate preprocessing for each algorithm.

For example:

- Linear Regression trained with gradient descent generally benefits from feature scaling.
- Ridge and Lasso generally benefit from feature scaling.
- Random Forest usually does not require feature scaling.
- XGBoost, LightGBM and CatBoost generally do not require feature scaling for their standard tree-based models.

If you have categorical features, make sure they are encoded or handled appropriately for each algorithm.

# 4. Understanding Parameters and Hyperparameters

This is one of the most important concepts in model tuning.

First, remember that models learn parameters during training.

### Parameters

Parameters are values learned by the model from training data.

For Linear Regression:

```python
w1 = 0.02
w2 = 2.5
w3 = -0.8
b = 1.0
```

These are learned parameters.

### Hyperparameters

Hyperparameters are settings that you choose before or during the training process.

Examples:

| Algorithm | Hyperparameters |
|---|---|
| Ridge | alpha |
| Lasso | alpha |
| Elastic Net | alpha, l1_ratio |
| Decision Tree | max_depth, min_samples_split |
| Random Forest | n_estimators, max_depth, max_features |
| Gradient Boosting | learning_rate, n_estimators, max_depth |
| XGBoost | learning_rate, max_depth, n_estimators |
| LightGBM | num_leaves, learning_rate, n_estimators |
| CatBoost | iterations, depth, learning_rate |

### Simple difference

| Parameters | Hyperparameters |
|---|---|
| Learned from training data | Set by the practitioner or a search procedure |
| Example: regression weights | Example: Ridge alpha |
| Part of the fitted model | Control how the model is trained |

Important:

A hyperparameter can be selected automatically using a search algorithm, but it is still a hyperparameter.

# 5. Understanding Hyperparameter Tuning

Suppose you are using Ridge Regression.

It has an important hyperparameter:

```python
alpha
```

Alpha controls the regularization strength.

You do not know which value will work best.

You can test different values:

```text
0.001
0.01
0.1
1
10
100
```

Train the model using different values and compare their validation performance.

This process is called **hyperparameter tuning**.

### Example

| Alpha | Validation RMSE |
|---:|---:|
| 0.001 | 9.5 |
| 0.01 | 8.8 |
| 0.1 | 8.1 |
| 1 | 7.8 |
| 10 | 8.5 |
| 100 | 12.0 |

In this illustrative example, alpha = 1 gives the lowest validation RMSE.

You would select that value among the tested candidates.

# 6. Grid Search

Grid Search is a hyperparameter tuning technique.

You provide a list of possible values for each hyperparameter.

The algorithm tests every possible combination.

### Example

Suppose a Decision Tree has two hyperparameters:

```python
max_depth = [2, 3, 5]

min_samples_split = [2, 5]
```

Grid Search tests:

| Experiment | max_depth | min_samples_split |
|---|---:|---:|
| 1 | 2 | 2 |
| 2 | 2 | 5 |
| 3 | 3 | 2 |
| 4 | 3 | 5 |
| 5 | 5 | 2 |
| 6 | 5 | 5 |

There are six combinations.

Grid Search evaluates all six.

### Python example

```python
from sklearn.model_selection import GridSearchCV

from sklearn.tree import DecisionTreeRegressor

model = DecisionTreeRegressor(
    random_state=42
)

parameters = {
    "max_depth": [2, 3, 5],
    "min_samples_split": [2, 5]
}

search = GridSearchCV(
    estimator=model,
    param_grid=parameters,
    cv=5,
    scoring="neg_mean_squared_error",
    n_jobs=-1
)

search.fit(X_train, y_train)

print("Best parameters:")
print(search.best_params_)

print("Best CV score:")
print(search.best_score_)
```

### Understanding the arguments

| Argument | Meaning |
|---|---|
| estimator | The model to tune |
| param_grid | Hyperparameter values to test |
| cv | Cross-validation strategy or number of folds |
| scoring | Metric used to compare models |
| n_jobs | Number of parallel jobs; -1 uses available processors |

### Important

Scikit-learn uses negative MSE for `neg_mean_squared_error`.

This is because its search procedures follow a convention where higher scoring values are better.

A score of -25 is better than -100 for this scoring method.

To express the corresponding MSE:

```python
best_mse = -search.best_score_

print(best_mse)
```

# 7. Random Search

Grid Search tests every combination in the specified grid.

But this can become expensive when you have many hyperparameters.

Random Search takes a different approach.

It samples a specified number of combinations from the search space.

### Example

Suppose you have:

```python
max_depth = [2, 3, 4, 5, 6, 7, 8, 9]

min_samples_split = [2, 3, 4, 5, 6, 7]

min_samples_leaf = [1, 2, 3, 4, 5]
```

The total number of combinations is:

```text
8 × 6 × 5 = 240
```

Grid Search would evaluate all 240 combinations.

Random Search might evaluate only 20 randomly selected combinations.

### Python example

```python
from sklearn.model_selection import RandomizedSearchCV

from sklearn.ensemble import RandomForestRegressor

from scipy.stats import randint

model = RandomForestRegressor(
    random_state=42
)

parameters = {
    "n_estimators": randint(100, 501),
    "max_depth": [None, 5, 10, 15, 20],
    "min_samples_split": randint(2, 11),
    "min_samples_leaf": randint(1, 6)
}

search = RandomizedSearchCV(
    estimator=model,
    param_distributions=parameters,
    n_iter=20,
    cv=5,
    scoring="neg_mean_squared_error",
    random_state=42,
    n_jobs=-1
)

search.fit(X_train, y_train)

print("Best parameters:")
print(search.best_params_)
```

### Understanding n_iter

```python
n_iter=20
```

This means the search evaluates 20 sampled hyperparameter combinations.

It does not mean 20 training examples or 20 epochs.

### Grid Search vs Random Search

| Grid Search | Random Search |
|---|---|
| Tests every specified combination | Tests sampled combinations |
| Can be expensive | Often cheaper for large search spaces |
| Useful for small search spaces | Useful for larger search spaces |
| Predictable search coverage | Search coverage is random |

Random Search can sometimes find a good configuration much faster than Grid Search.

But it does not guarantee that it finds the global best combination.

# 8. Understanding Cross-Validation

Cross-validation is a method used to evaluate how a model performs across different splits of the training data.

Why do we need it?

Imagine your dataset contains 1,000 houses.

You randomly divide it into:

- Training: 800 houses.
- Validation: 200 houses.

You train a model and calculate validation RMSE.

But perhaps those 200 validation houses are unusually easy to predict.

Your score might not represent the model's general performance.

Cross-validation helps reduce dependence on one particular split.

## 8.1 K-Fold Cross-Validation

Suppose you have 1,000 training examples and choose:

```python
cv = 5
```

The training data is divided into five folds.

Each fold is used once for validation, while the other four folds are used for training.

### Example

```text
Round 1:
Training: Fold 2 + Fold 3 + Fold 4 + Fold 5
Validation: Fold 1

Round 2:
Training: Fold 1 + Fold 3 + Fold 4 + Fold 5
Validation: Fold 2

Round 3:
Training: Fold 1 + Fold 2 + Fold 4 + Fold 5
Validation: Fold 3

Round 4:
Training: Fold 1 + Fold 2 + Fold 3 + Fold 5
Validation: Fold 4

Round 5:
Training: Fold 1 + Fold 2 + Fold 3 + Fold 4
Validation: Fold 5
```

Every example is used for validation exactly once.

### Example scores

| Fold | Validation RMSE |
|---|---:|
| 1 | 8 |
| 2 | 9 |
| 3 | 7 |
| 4 | 10 |
| 5 | 8 |

Average RMSE:

```text
(8 + 9 + 7 + 10 + 8) / 5

= 8.4
```

The average gives a summary across the five validation folds.

You can also calculate the standard deviation to understand how much the scores vary across folds.

### Python example

```python
from sklearn.model_selection import KFold

from sklearn.model_selection import cross_val_score

from sklearn.linear_model import LinearRegression

model = LinearRegression()

cv = KFold(
    n_splits=5,
    shuffle=True,
    random_state=42
)

scores = cross_val_score(
    model,
    X_train,
    y_train,
    cv=cv,
    scoring="neg_mean_squared_error"
)

mse_scores = -scores

rmse_scores = mse_scores ** 0.5

print("Fold RMSE:", rmse_scores)

print("Average RMSE:", rmse_scores.mean())

print("Standard deviation:", rmse_scores.std())
```

This example assumes that the training data is suitable for shuffled K-Fold validation.

For time-series data, do not randomly mix past and future observations.

# 9. Other Cross-Validation Methods

K-Fold is not the only cross-validation method.

## 9.1 Stratified K-Fold

Stratified K-Fold preserves class proportions across folds.

It is mainly used for classification problems.

For ordinary continuous-target regression, standard K-Fold is more common.

If you want to stratify regression data, you may need to create meaningful target bins first. This must be done carefully.

## 9.2 Leave-One-Out Cross-Validation

Leave-One-Out Cross-Validation is an extreme form of cross-validation.

If you have 100 examples:

- Train on 99 examples.
- Validate on the remaining 1 example.
- Repeat 100 times.

It can be computationally expensive.

It is generally not necessary for large datasets.

## 9.3 TimeSeriesSplit

This method is important for time-series prediction.

Imagine you are predicting cryptocurrency prices.

Your dataset contains:

```text
January
February
March
April
May
June
```

You must not train using future information to predict the past.

TimeSeriesSplit preserves chronological order.

Simplified example:

```text
Split 1:
Train: January, February
Test: March

Split 2:
Train: January, February, March
Test: April

Split 3:
Train: January, February, March, April
Test: May

Split 4:
Train: January, February, March, April, May
Test: June
```

### Python example

```python
from sklearn.model_selection import TimeSeriesSplit

cv = TimeSeriesSplit(
    n_splits=5
)

for train_index, test_index in cv.split(X_train):

    X_fold_train = X_train.iloc[train_index]

    X_fold_test = X_train.iloc[test_index]

    y_fold_train = y_train.iloc[train_index]

    y_fold_test = y_train.iloc[test_index]

    print(
        len(X_fold_train),
        len(X_fold_test)
    )
```

This example assumes that the data is sorted chronologically and uses Pandas objects.

TimeSeriesSplit can also be configured with a gap between training and validation observations.

That is useful when nearby observations could cause leakage.

# 10. Grid Search with Cross-Validation

Now connect the concepts.

Grid Search tests different hyperparameter combinations.

Cross-validation evaluates each combination across multiple folds.

Suppose you are tuning a Random Forest.

```python
from sklearn.model_selection import GridSearchCV

from sklearn.ensemble import RandomForestRegressor

model = RandomForestRegressor(
    random_state=42
)

parameters = {
    "n_estimators": [100, 200, 300],
    "max_depth": [5, 10, 15, None],
    "min_samples_split": [2, 5]
}

search = GridSearchCV(
    estimator=model,
    param_grid=parameters,
    cv=5,
    scoring="neg_mean_squared_error",
    n_jobs=-1
)

search.fit(X_train, y_train)

print(search.best_params_)
```

The search evaluates each hyperparameter combination using five cross-validation folds.

There are:

```text
3 × 4 × 2 = 24 combinations
```

Each combination is evaluated across five folds.

That means 120 model fits, plus a final refit when `refit=True`, which is the default.

This can require considerable computation.

# 11. Understanding Random Forest Hyperparameters

Let's understand common Random Forest settings.

## 11.1 n_estimators

The number of decision trees in the forest.

Example:

```python
RandomForestRegressor(
    n_estimators=200
)
```

This creates a forest with 200 trees.

Increasing the number of trees can improve stability, but it also increases computation.

More trees do not always produce better validation performance.

## 11.2 max_depth

Controls the maximum depth of each tree.

Example:

```python
RandomForestRegressor(
    max_depth=10
)
```

A shallow tree is less complex.

A deep tree can learn more complicated patterns but may overfit.

`None` means that the tree can continue splitting until other stopping conditions are met.

## 11.3 min_samples_split

The minimum number of training samples required for a node to be split.

Example:

```python
RandomForestRegressor(
    min_samples_split=5
)
```

A node needs at least five samples before it can be considered for splitting.

Increasing this value can make trees simpler.

## 11.4 min_samples_leaf

The minimum number of training samples required in a leaf node.

Example:

```python
RandomForestRegressor(
    min_samples_leaf=3
)
```

Each leaf must contain at least three training examples.

Larger values can make predictions smoother and reduce overfitting.

## 11.5 max_features

Controls how many input features are considered when looking for the best split.

It affects the diversity of the trees in the forest.

The exact accepted values and defaults depend on the estimator and scikit-learn version.

### Model selection

You choose which algorithm to use.

Example:

```text
Linear Regression
vs
Ridge Regression
vs
Random Forest
vs

```

### Hyperparameter tuning

You choose suitable settings for a particular algorithm.

Example:

```text

```

### Simple comparison

| Model selection | Hyperparameter tuning |
|---|---|
| Chooses an algorithm | Chooses its settings |

# 13. Avoiding Data Leakage During Model Selection

This is extremely important.

Imagine you have:

- Training data.
- Validation data.
- Test data.

You use the validation data to compare models and tune hyperparameters.

You should keep the test data separate until final evaluation.

### Correct workflow

```text
Complete dataset
       |
       v
Train / Validation / Test
       |
       v
Model selection and tuning
using training and validation
       |
       v
Select final model
       |
       v
Evaluate once on test data
```

With cross-validation, the training portion is divided into multiple training and validation folds.

The test set remains untouched.

## 13.1 What Is Preprocessing Leakage?

Suppose you standardize the entire training dataset before cross-validation.

Then validation-fold information can influence the scaling parameters used during that fold's training.

A safer approach is to place preprocessing inside a Scikit-Learn Pipeline.

Example:

```python
from sklearn.pipeline import Pipeline

from sklearn.impute import SimpleImputer

from sklearn.preprocessing import StandardScaler

from sklearn.linear_model import Ridge

pipeline = Pipeline([
    (
        "imputer",
        SimpleImputer(strategy="median")
    ),
    (
        "scaler",
        StandardScaler()
    ),
    (
        "model",
        Ridge()
    )
])
```

Now use the complete pipeline in Grid Search:

```python
from sklearn.model_selection import GridSearchCV

parameters = {
    "model__alpha": [
        0.01,
        0.1,
        1,
        10,
        100
    ]
}

search = GridSearchCV(
    estimator=pipeline,
    param_grid=parameters,
    cv=5,
    scoring="neg_mean_squared_error"
)

search.fit(X_train, y_train)
```

For each fold, the pipeline learns imputation and scaling parameters using only that fold's training portion.

This helps prevent preprocessing leakage.

### Important

The same principle applies to:

- Missing-value imputation.
- Feature scaling.
- Feature selection.
- Categorical encoding.
- Other transformations that learn information from data.

Fit these transformations only on the training portion of each fold.

# 14. A Complete Model Selection Experiment

Let's compare three regression algorithms.

We will use:

1. Linear Regression.
2. Ridge Regression.
3. Random Forest Regression.

The following example assumes:

- `X_train` and `y_train` are already prepared.
- `X_test` and `y_test` are held back for final evaluation.
- All input features are numerical and have no missing values.
- The dataset is suitable for shuffled K-Fold validation.

### Step 1: Import models

```python
from sklearn.linear_model import LinearRegression

from sklearn.linear_model import Ridge

from sklearn.ensemble import RandomForestRegressor
```

### Step 2: Create models

```python
models = {
    "Linear Regression": LinearRegression(),

    "Ridge Regression": Ridge(
        alpha=1.0
    ),

    "Random Forest": RandomForestRegressor(
        n_estimators=200,
        random_state=42
    )
}
```

### Step 3: Train and evaluate using cross-validation

```python
import numpy as np

from sklearn.model_selection import cross_val_score

from sklearn.model_selection import KFold

cv = KFold(
    n_splits=5,
    shuffle=True,
    random_state=42
)

for name, model in models.items():

    scores = cross_val_score(
        model,
        X_train,
        y_train,
        cv=cv,
        scoring="neg_mean_squared_error"
    )

    rmse_scores = np.sqrt(-scores)

    print(name)

    print(
        "Average RMSE:",
        rmse_scores.mean()
    )

    print(
        "Standard deviation:",
        rmse_scores.std()
    )

    print()
```

### Step 4: Select a model

Compare:

- Average validation RMSE.
- Variation across folds.
- Training time.
- Prediction speed.
- Model complexity.
- Interpretability.

Do not choose a model based on one metric alone if other project requirements matter.

### Step 5: Final evaluation

After selecting and tuning your model:

```python
best_model.fit(X_train, y_train)

predictions = best_model.predict(X_test)
```

Calculate the final test metrics:

```python
from sklearn.metrics import mean_absolute_error

from sklearn.metrics import mean_squared_error

mae = mean_absolute_error(
    y_test,
    predictions
)

rmse = np.sqrt(
    mean_squared_error(
        y_test,
        predictions
    )
)

print("Test MAE:", mae)

print("Test RMSE:", rmse)
```

Here, `best_model` represents the selected and configured estimator or pipeline.

For a more complete experiment, preserve a separate validation strategy during model selection and use the test set only for the final evaluation.

# 15. Important Mistakes to Avoid

| Mistake | Why it is a problem |
|---|---|
| Choosing a model using training RMSE alone | Can select an overfitted model |
| Tuning on the test set repeatedly | Makes test performance unreliable |
| Using random K-Fold for time-series prediction | Can allow future information into training |
| Searching too many combinations | Can waste time and computing resources |
| Scaling data before cross-validation | Can cause preprocessing leakage |
| Ignoring variation between folds | One average score may hide unstable performance |
| Assuming the most complex model is best | Complexity does not guarantee generalization |
| Ignoring inference speed and memory | A model may be too expensive for production |
| Preprocessing validation data using training-and-validation statistics | Can introduce information leakage |

# 17. Final Understanding

Building a regression model is not just about selecting an algorithm and calling `.fit()`.

A proper model-development process involves:

1. Understanding the problem.
2. Preparing the data.
3. Selecting suitable algorithms.
4. Comparing models fairly.
5. Tuning hyperparameters.
6. Using cross-validation.
7. Avoiding data leakage.
8. Selecting the final model.
9. Evaluating it on untouched test data.

The objective is to find a model that performs reliably on new, unseen data, not simply one that memorizes the training dataset.
