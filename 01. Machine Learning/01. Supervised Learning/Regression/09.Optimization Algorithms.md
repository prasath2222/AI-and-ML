
# Optimization Algorithms in Machine Learning

# 1. Introduction

Optimization algorithms are methods used to improve the learning process of machine learning models.

During training, a model has parameters such as:

- Weights
- Biases

The model makes predictions using these parameters.

A loss function measures how wrong those predictions are.

An optimization algorithm changes the model parameters to reduce the loss.

The general training process is:

1. Model receives training data.
2. Model calculates predictions.
3. Loss function measures prediction errors.
4. Gradients are calculated.
5. Optimizer updates model parameters.
6. Training repeats.

Gradient Descent is one optimization method.

However, ordinary Gradient Descent has limitations:

- It can move slowly through some loss landscapes.
- It can zigzag in narrow valleys.
- It can struggle with gradients of very different magnitudes.
- It can have difficulty with noisy gradients.
- Choosing a suitable learning rate can be difficult.

Several optimization algorithms have been developed to address these problems.

Important optimization algorithms include:

1. Stochastic Gradient Descent (SGD)
2. SGD with Momentum
3. Nesterov Accelerated Gradient (NAG)
4. AdaGrad
5. RMSprop
6. Adam
7. AdamW

---

# 2. First Understand: What Is an Optimizer?

An optimizer is responsible for updating the model's trainable parameters using calculated gradients.

For example, suppose a model has:

```python
w1 = 0.5
w2 = 0.8
b = 1.0
```

After calculating gradients:

```python
w1_gradient = -0.4
w2_gradient = 0.2
b_gradient = -0.1
```

An optimizer uses these gradients to calculate new parameter values.

Different optimizers use different update strategies.

### Important distinction

Gradient calculation and parameter updating are separate operations.

**Gradient calculation:**

Determines how the loss changes with respect to each parameter.

**Optimizer:**

Uses those gradients to update the parameters.

In PyTorch:

```python
loss.backward()
```

Calculates gradients.

```python
optimizer.step()
```

Updates model parameters.

---

# PART 1: STOCHASTIC GRADIENT DESCENT (SGD)

# 3. What Is SGD?

SGD stands for Stochastic Gradient Descent.

It updates model parameters using gradients calculated from training examples or mini-batches.

In modern deep-learning libraries, SGD is commonly used with mini-batches rather than one individual example at a time.

The basic update equation is:

New parameter = Old parameter - Learning rate × Gradient

Mathematically:

θ_new = θ_old - η × g

Where:

- θ = Model parameter.
- η = Learning rate.
- g = Gradient.

### Example

```python
weight = 0.5

gradient = -0.4

lr = 0.1

weight = weight - (lr * gradient)

print(weight)
```

Calculation:

```text
New weight = 0.5 - (0.1 × -0.4)

New weight = 0.54
```

The parameter changes from 0.5 to 0.54.

### How does SGD work?

1. Receive a training batch.
2. Calculate predictions.
3. Calculate loss.
4. Calculate gradients.
5. Update parameters.
6. Move to the next batch.

### Advantages

- Simple implementation.
- Low additional memory requirement.
- Effective for many machine learning problems.
- Provides a useful baseline for optimizer comparisons.

### Limitations

- Can zigzag in certain loss landscapes.
- May produce noisy updates.
- Can require careful learning-rate tuning.
- May converge slowly in some situations.

---

# 4. SGD in PyTorch

```python
import torch
import torch.nn as nn

model = nn.Linear(3, 1)

optimizer = torch.optim.SGD(
    model.parameters(),
    lr=0.01
)
```

Training:

```python
for batch_x, batch_y in loader:

    predictions = model(batch_x)

    loss = loss_function(
        predictions,
        batch_y
    )

    optimizer.zero_grad()

    loss.backward()

    optimizer.step()
```

The optimizer updates the parameters using the calculated gradients.

### Important

PyTorch's SGD optimizer can also support momentum, weight decay and Nesterov momentum.

# PART 2: SGD WITH MOMENTUM

# 5. Why Was Momentum Introduced?

Imagine a ball rolling down a hill.

If the ball repeatedly moves in the same direction, it builds momentum.

This helps it continue moving in that direction.

Momentum optimization uses a similar idea.

Instead of considering only the current gradient, it also remembers information from previous gradients.

This helps reduce zigzagging and can accelerate movement in consistent directions.

### Problem without momentum

Imagine the gradients are:

```text
Iteration 1: 10
Iteration 2: -8
Iteration 3: 9
Iteration 4: -7
```

The gradient direction keeps changing.

The parameter updates can zigzag.

Momentum uses previous gradient information to smooth the update direction.

---

# 6. How Momentum Works

Momentum maintains an additional value called velocity.

Velocity stores information about previous gradients.

A common momentum formulation is:

v_t = β × v_(t-1) + g_t

θ_t = θ_(t-1) - η × v_t

Where:

- v_t = Current velocity.
- v_(t-1) = Previous velocity.
- β = Momentum coefficient.
- g_t = Current gradient.
- η = Learning rate.
- θ_t = Current parameter.

The momentum coefficient is commonly chosen between 0 and 1.

For example:

```python
momentum = 0.9
```

A value of 0.9 means previous velocity has a strong influence on the current velocity.

### Step-by-step numerical example

Suppose:

```python
previous_velocity = 0.0

gradient = 10.0

momentum = 0.9
```

Calculate new velocity:

```text
velocity = (0.9 × 0) + 10

velocity = 10
```

Now suppose the next gradient is 8:

```text
velocity = (0.9 × 10) + 8

velocity = 17
```

The previous gradient contributes to the new velocity.

The optimizer therefore remembers some of its previous movement.

### Important

Momentum does not simply add the previous gradient directly.

It maintains a weighted history through the velocity calculation.

---

# 7. Momentum: Python Implementation

```python
weight = 0.5

lr = 0.1

momentum = 0.9

velocity = 0.0

gradients = [10, 8, 6, 4]

for gradient in gradients:

    velocity = (
        momentum * velocity
        + gradient
    )

    weight = weight - (lr * velocity)

    print(weight)
```

This is a simplified one-parameter demonstration.

In a real model, each parameter has its own velocity.

### Advantages

- Reduces zigzagging in many optimization problems.
- Uses information from previous gradients.
- Can accelerate optimization in consistent directions.
- Often improves training efficiency.

### Limitations

- Introduces an additional hyperparameter.
- Requires extra memory for velocity.
- Still requires learning-rate tuning.
- Does not guarantee reaching the global minimum.

---

# 8. Momentum in PyTorch

```python
optimizer = torch.optim.SGD(
    model.parameters(),
    lr=0.01,
    momentum=0.9
)
```

The main difference from ordinary SGD is:

```python
momentum=0.9
```

PyTorch maintains the momentum state internally.

You do not need to calculate velocity manually.

# PART 3: NESTEROV ACCELERATED GRADIENT

# 9. What Is Nesterov Momentum?

Nesterov Accelerated Gradient (NAG) is a momentum-based optimization method.

It is related to ordinary momentum, but changes how the gradient is evaluated.

Ordinary momentum uses the gradient at the current parameter position.

Nesterov momentum first considers where the momentum update is expected to take the parameters.

It then calculates the gradient at that anticipated position.

This is often described as a look-ahead gradient.

### Simple example

Imagine you are moving toward the bottom of a valley.

Ordinary momentum:

1. Check the current position.
2. Calculate the gradient.
3. Use momentum to move.

Nesterov momentum:

1. Estimate where momentum will take you.
2. Look at the slope at that anticipated position.
3. Adjust the movement using that information.

This can help correct movement earlier.

---

# 10. Nesterov Momentum Mathematics

A common formulation is:

v_t = β × v_(t-1) + ∇L(θ_(t-1) - η × β × v_(t-1))

θ_t = θ_(t-1) - η × v_t

Where:

- θ = Model parameters.
- v = Velocity.
- β = Momentum coefficient.
- η = Learning rate.
- ∇L = Gradient of the loss function.

The important difference is that the gradient is evaluated at a look-ahead position.

### Ordinary Momentum vs Nesterov

| Ordinary Momentum | Nesterov Momentum |
|---|---|
| Uses current-position gradient | Uses look-ahead gradient |
| Accumulates velocity | Accumulates velocity |
| Can reduce zigzagging | Can improve correction of movement |
| Momentum-based | Momentum-based |

### Advantages

- Can improve optimization in some situations.
- Uses anticipated parameter movement.
- Often works well with SGD.

### Limitations

- Requires additional implementation complexity.
- Still needs hyperparameter tuning.
- Is not guaranteed to outperform ordinary momentum.

---

# 11. Nesterov in PyTorch

```python
optimizer = torch.optim.SGD(
    model.parameters(),
    lr=0.01,
    momentum=0.9,
    nesterov=True
)
```

Nesterov requires momentum to be enabled.

# PART 4: ADAGRAD

# 12. Why Was AdaGrad Introduced?

Ordinary SGD generally uses one shared learning rate for parameter updates.

However, different parameters may receive gradients of very different magnitudes.

Some parameters may receive large gradients frequently.

Others may receive small or infrequent gradients.

AdaGrad addresses this by adapting the learning rate separately for each parameter.

It uses the history of squared gradients.

### Basic idea

Parameters that have accumulated large squared gradients receive smaller effective learning rates.

Parameters with smaller accumulated squared gradients receive relatively larger effective learning rates.

This allows different parameters to have different effective learning rates.

---

# 13. How AdaGrad Works

AdaGrad maintains an accumulated squared-gradient value.

Mathematically:

G_t = G_(t-1) + g_t²

Then it updates:

θ_t = θ_(t-1) - η × g_t / (√G_t + ε)

Where:

- G_t = Accumulated squared gradients.
- g_t = Current gradient.
- η = Initial learning rate.
- ε = Small value for numerical stability.
- θ = Model parameter.

Each parameter maintains its own accumulated squared-gradient value.

### Numerical example

Suppose:

```python
gradient = 4.0

accumulated_squared_gradient = 0.0

lr = 0.1

epsilon = 1e-8
```

First, square the gradient:

```text
4² = 16
```

Accumulate:

```text
G = 0 + 16

G = 16
```

Calculate the effective update:

```text
Update = 0.1 × 4 / √16

Update = 0.1
```

The parameter update is approximately 0.1.

If another gradient arrives, its square is added to the accumulated value.

As the accumulated value grows, the effective learning rate generally decreases.

---

# 14. AdaGrad: Python Implementation

```python
weight = 0.5

lr = 0.1

epsilon = 1e-8

accumulated_gradient = 0.0

gradients = [4, 3, 2, 1]

for gradient in gradients:

    accumulated_gradient += gradient ** 2

    update = (
        lr * gradient
        / ((accumulated_gradient ** 0.5) + epsilon)
    )

    weight = weight - update

    print(weight)
```

This example demonstrates one parameter.

For multiple parameters, each parameter needs its own accumulated squared-gradient value.

### Advantages

- Adapts learning rates separately for parameters.
- Can work well with sparse features.
- Reduces the need for one manually chosen effective learning rate for every parameter.

### Limitations

- Accumulated squared gradients continually increase.
- Effective learning rates can become extremely small.
- Training may stop making useful progress.

This decreasing-learning-rate behaviour is one major limitation of AdaGrad.

---

# 15. AdaGrad in PyTorch

```python
optimizer = torch.optim.Adagrad(
    model.parameters(),
    lr=0.01
)
```

PyTorch maintains the accumulated squared-gradient state internally.

# PART 5: RMSPROP

# 16. Why Was RMSprop Introduced?

AdaGrad accumulates squared gradients throughout training.

This can cause the effective learning rate to become extremely small.

RMSprop addresses this by using an exponentially weighted moving average of squared gradients.

Instead of remembering all squared gradients equally, it gives more importance to recent gradients.

### Simple idea

AdaGrad:

```text
Keep accumulating squared gradients.
```

RMSprop:

```text
Keep a moving average of squared gradients.
```

Older gradient information gradually loses influence.

---

# 17. How RMSprop Works

RMSprop maintains an exponential moving average of squared gradients.

Mathematically:

s_t = ρ × s_(t-1) + (1 - ρ) × g_t²

Parameter update:

θ_t = θ_(t-1) - η × g_t / (√s_t + ε)

Where:

- s_t = Moving average of squared gradients.
- ρ = Decay rate.
- g_t = Current gradient.
- η = Learning rate.
- ε = Small numerical-stability value.

A common starting value for ρ is 0.9.

### Numerical example

Suppose:

```python
gradient = 4.0

previous_average = 0.0

rho = 0.9
```

Calculate:

```text
s = (0.9 × 0) + (0.1 × 4²)

s = 1.6
```

The squared gradient contributes to the moving average.

On the next update, the previous average is retained with a factor of 0.9, and the new squared gradient is added with a factor of 0.1.

---

# 18. RMSprop: Python Implementation

```python
weight = 0.5

lr = 0.01

rho = 0.9

epsilon = 1e-8

squared_gradient_average = 0.0

gradients = [4, 3, 2, 1]

for gradient in gradients:

    squared_gradient_average = (
        rho * squared_gradient_average
        + (1 - rho) * gradient ** 2
    )

    update = (
        lr * gradient
        / (
            squared_gradient_average ** 0.5
            + epsilon
        )
    )

    weight = weight - update

    print(weight)
```

### Advantages

- Adapts learning rates for individual parameters.
- Uses recent gradient information.
- Avoids AdaGrad's continuously growing squared-gradient accumulator.
- Can work well with noisy or non-stationary gradients.

### Limitations

- Requires tuning its hyperparameters.
- Does not guarantee better performance than other optimizers.
- Can still require careful learning-rate selection.

---

# 19. RMSprop in PyTorch

```python
optimizer = torch.optim.RMSprop(
    model.parameters(),
    lr=0.001,
    alpha=0.99
)
```

The `alpha` argument controls the decay rate of the moving average in PyTorch's implementation.

# PART 6: ADAM

# 20. What Is Adam?

Adam stands for Adaptive Moment Estimation.

Adam combines ideas from:

1. Momentum.
2. Adaptive learning rates.

It maintains two moving averages:

- First moment: Moving average of gradients.
- Second moment: Moving average of squared gradients.

The first moment provides information about gradient direction.

The second moment provides information about gradient magnitude.

Adam also uses bias correction for its moving averages.

It is widely used for training deep neural networks.

---

# 21. Why Does Adam Combine Two Ideas?

Momentum remembers previous gradient directions.

RMSprop adapts parameter updates using recent squared-gradient information.

Adam combines both ideas.

### First moment

The first moment estimates the average gradient.

It is similar to momentum.

### Second moment

The second moment estimates the average squared gradient.

It is similar to RMSprop.

By combining these two estimates, Adam adapts updates using both gradient direction and magnitude.

---

# 22. Adam Mathematics

First moment:

m_t = β₁ × m_(t-1) + (1 - β₁) × g_t

Second moment:

v_t = β₂ × v_(t-1) + (1 - β₂) × g_t²

Bias correction:

m̂_t = m_t / (1 - β₁ᵗ)

v̂_t = v_t / (1 - β₂ᵗ)

Parameter update:

θ_t = θ_(t-1) - η × m̂_t / (√v̂_t + ε)

Where:

- m_t = First moment estimate.
- v_t = Second moment estimate.
- β₁ = First-moment decay rate.
- β₂ = Second-moment decay rate.
- g_t = Current gradient.
- η = Learning rate.
- ε = Small numerical-stability value.

Common starting settings:

```python
lr = 0.001

beta1 = 0.9

beta2 = 0.999

epsilon = 1e-8
```

These are common defaults, not universal best settings.

---

# 23. Why Does Adam Need Bias Correction?

At the beginning of training:

```python
m = 0

v = 0
```

The moving averages start at zero.

Early moving-average estimates can therefore be biased toward zero.

Adam corrects this initial bias.

It calculates:

```text
m_hat = m / (1 - beta1 ** t)

v_hat = v / (1 - beta2 ** t)
```

Where `t` is the update step number.

Bias correction helps the early estimates better represent the observed gradients.

---

# 24. Adam: Python Implementation

The following is a simplified implementation for one parameter.

```python
weight = 0.5

lr = 0.001

beta1 = 0.9

beta2 = 0.999

epsilon = 1e-8

m = 0.0

v = 0.0

t = 0

gradients = [4, 3, 2, 1]

for gradient in gradients:

    t += 1

    # First moment

    m = (
        beta1 * m
        + (1 - beta1) * gradient
    )

    # Second moment

    v = (
        beta2 * v
        + (1 - beta2) * gradient ** 2
    )

    # Bias correction

    m_hat = m / (1 - beta1 ** t)

    v_hat = v / (1 - beta2 ** t)

    # Parameter update

    weight = weight - (
        lr * m_hat
        / ((v_hat ** 0.5) + epsilon)
    )

    print(weight)
```

This example demonstrates Adam's calculations for one parameter.

In a real model, each parameter maintains its own first- and second-moment states.

### Advantages

- Combines momentum and adaptive learning rates.
- Often works well with default hyperparameters.
- Useful for many deep-learning problems.
- Handles parameters with different gradient magnitudes.
- Often provides fast initial progress.

### Limitations

- Uses additional memory for moment estimates.
- May require tuning.
- Does not guarantee better generalization.
- May not outperform SGD with momentum in every task.

---

# 25. Adam in PyTorch

```python
optimizer = torch.optim.Adam(
    model.parameters(),
    lr=0.001
)
```

A more explicit configuration:

```python
optimizer = torch.optim.Adam(

```

# PART 7: ADAMW

# 26. Why Was AdamW Introduced?

Adam commonly supports weight decay.

However, applying weight decay directly through the gradient in adaptive optimizers can behave differently from decoupled weight decay.

AdamW separates weight decay from Adam's gradient-based adaptive update.

This is called decoupled weight decay.

### What is weight decay?

Weight decay discourages excessively large parameter values.

It helps control model complexity.

For example, a simplified weight-decay update includes:

```text
Parameter = Parameter - Learning rate × Weight decay × Parameter
```

AdamW separates this decay operation from the adaptive gradient update.

---

# 27. Adam vs AdamW

| Adam | AdamW |
|---|---|
| Adaptive moment estimation | Adaptive moment estimation |
| Uses first and second moments | Uses first and second moments |
| Weight decay may be coupled to gradient implementation | Weight decay is decoupled |
| Common deep-learning optimizer | Common deep-learning optimizer |

### Why is decoupling useful?

It makes weight decay behave independently of Adam's adaptive gradient scaling.

This provides a clearer and often more effective way to apply weight decay.

---

# 28. AdamW in PyTorch

```python
optimizer = torch.optim.AdamW(
    model.parameters(),
    lr=0.001,
    weight_decay=0.01
)
```

Here:

- `lr` controls the learning rate.
- `weight_decay` controls the decoupled weight-decay strength.

Weight decay is not a replacement for validation or proper model evaluation.

|---|---|---|

| Optimizer | Advantages | Limitations |
|---|---|---|
| SGD | Simple, low memory | Can zigzag, needs tuning |
| Momentum | Reduces zigzagging | Extra hyperparameter and memory |
| Nesterov | Look-ahead correction | More implementation complexity |
| AdaGrad | Useful for sparse gradients | Learning rate can become too small |
| RMSprop | Adapts to recent gradients | Requires tuning |
| Adam | Adaptive and often fast | Extra memory, not always best |
| AdamW | Decoupled weight decay | Still requires tuning |

# 31. When Should We Use Each Optimizer?

### SGD

Useful as a simple baseline and for problems where its generalization performance is strong.

### SGD with Momentum

Useful when updates zigzag and consistent movement needs acceleration.

### Nesterov Momentum

Useful when a look-ahead momentum method is desired.

### AdaGrad

Useful in some sparse-gradient problems.

### RMSprop

Useful when adaptive updates based on recent gradient magnitudes are beneficial.

### Adam

A strong starting point for many neural-network training tasks.

### AdamW

A common choice for neural networks when decoupled weight decay is desired.

There is no universally best optimizer.

Performance depends on:

- Dataset.
- Model architecture.
- Learning rate.
- Batch size.
- Loss function.
- Training duration.
- Evaluation objective.

# PART 9: PRACTICAL PYTORCH IMPLEMENTATION

# 32. Compare Optimizers Using the Same Model

We can experiment with different optimizers.

```python
import torch
import torch.nn as nn

model = nn.Linear(3, 1)
```

Define different optimizers:

```python
sgd = torch.optim.SGD(
    model.parameters(),
    lr=0.01
)

momentum = torch.optim.SGD(
    model.parameters(),
    lr=0.01,
    momentum=0.9
)

adagrad = torch.optim.Adagrad(
    model.parameters(),
    lr=0.01
)

rmsprop = torch.optim.RMSprop(
    model.parameters(),
    lr=0.001
)

adam = torch.optim.Adam(
    model.parameters(),
    lr=0.001
)

adamw = torch.optim.AdamW(
    model.parameters(),
    lr=0.001,
    weight_decay=0.01
)
```

### Important experimental rule

Do not train all optimizers sequentially on the same already-trained model and treat the results as a fair comparison.

For a fair experiment:

1. Create a fresh model for each optimizer.
2. Use identical initial model weights.
3. Use the same training and validation datasets.
4. Use comparable training budgets.
5. Tune learning rates appropriately.
6. Record training and validation results.

This avoids confusing optimizer effects with differences in initial conditions.

# 33. Complete Optimizer Training Loop

```python
for epoch in range(epochs):

    model.train()

    for batch_x, batch_y in loader:

        predictions = model(batch_x)

        loss = loss_function(
            predictions,
            batch_y
        )

        optimizer.zero_grad()

        loss.backward()

        optimizer.step()
```

Only the optimizer initialization changes when switching between optimizers.

The basic training-loop structure remains similar.

# PART 10: ADVANCED CONCEPTS

# 34. Hyperparameters of Optimizers

Hyperparameters are settings selected before or during training.

Important optimizer hyperparameters include:

| Hyperparameter | Meaning |
|---|---|
| Learning rate | Controls update size |
| Momentum | Controls contribution from previous velocity |
| Beta 1 | Controls first-moment decay |
| Beta 2 | Controls second-moment decay |
| Epsilon | Numerical-stability value |
| Weight decay | Controls parameter decay |
| Alpha / rho | Controls moving-average decay in relevant optimizers |

These settings affect how optimization behaves.

---

# 35. Optimizer State

Some optimizers maintain information across training updates.

Examples:

- Momentum maintains velocity.
- AdaGrad maintains accumulated squared gradients.
- RMSprop maintains squared-gradient averages.
- Adam maintains first- and second-moment estimates.

This stored information is called optimizer state.

It is important when saving and resuming model training.

In PyTorch:

```python
torch.save(
    optimizer.state_dict(),
    "optimizer_state.pth"
)
```

Loading:

```python
optimizer.load_state_dict(
    torch.load(
        "optimizer_state.pth",
        weights_only=True
    )
)
```

The model parameters and optimizer state should both be saved when exact training continuation is required.

---

# 36. Learning Rate Schedulers vs Optimizers

These are related but different concepts.

### Optimizer

Determines how model parameters are updated using gradients.

Examples:

- SGD.
- Adam.
- RMSprop.
- AdamW.

### Learning rate scheduler

Changes the learning rate during training.

Examples:

- StepLR.
- ExponentialLR.
- CosineAnnealingLR.
- ReduceLROnPlateau.

A scheduler does not replace an optimizer.

It adjusts the learning rate used by the optimizer.

Example:

```python
optimizer = torch.optim.Adam(
    model.parameters(),
    lr=0.001
)

scheduler = torch.optim.lr_scheduler.StepLR(
    optimizer,
    step_size=10,
    gamma=0.5
)
```

After each epoch:

```python
scheduler.step()
```

The learning rate is reduced according to the scheduler's rules.

For `ReduceLROnPlateau`, the scheduler is normally stepped using a monitored validation metric.

---

# 37. Common Optimizer Mistakes

1. Assuming Adam is always better than SGD.
2. Using the same learning rate for every optimizer without testing.
3. Comparing optimizers with different initial model weights.
4. Forgetting to clear gradients.
5. Forgetting to update optimizer parameters.
6. Using weight decay without understanding its effect.
7. Confusing learning-rate scheduling with optimization.
8. Ignoring validation performance.
9. Comparing optimizers using training loss alone.
10. Assuming faster initial loss reduction means better final generalization.
11. Forgetting to save optimizer state when resuming training.
12. Changing several hyperparameters simultaneously and making comparisons difficult.
