
# Regularization in Regression — Complete Guide

# 1. What Is Regularization?

Regularization is a technique used in Machine Learning to control model complexity by adding a penalty to the training objective.

Its main purpose is to help reduce overfitting.

### First, understand the problem

Imagine building a house-price prediction model.

```python
size = [1000, 1500, 2000, 2500]
bedrooms = [2, 3, 3, 4]
age = [10, 8, 5, 2]
```

The model learns weights:

```python
w1 = 0.02
w2 = 2.5
w3 = -0.8
b = 1.0
```

Now imagine creating many additional features:

```text
size
bedrooms
age
size_squared
age_squared
size_age
size_per_bedroom
```

The model becomes more flexible.

It might learn the training data extremely well, including unusual patterns that do not represent the real relationship.

As a result:

- Training performance may become excellent.
- Performance on unseen data may become poor.

This is called overfitting.

### Simple Definition

Regularization adds an additional penalty to the model's training objective to discourage unnecessarily large coefficients and help control model complexity.

IMPORTANT:

Regularization does not guarantee that overfitting will disappear. It is one technique for controlling it.

---

# 2. Understanding the Problem Before Regularization

Suppose our regression model is:

```text
Prediction = w1 × x1 + w2 × x2 + b
```

Where:

- x1 = House size.
- x2 = Number of bedrooms.
- w1 and w2 = Model weights.
- b = Bias.

The model tries to make predictions close to actual prices.

Example:

| Actual price | Predicted price | Error |
|---:|---:|---:|
| 20 | 21 | -1 |
| 30 | 29 | 1 |
| 40 | 41 | -1 |
| 50 | 49 | 1 |

The model has small prediction errors.

But imagine another model learns unnecessarily large weights and complicated combinations of features to fit every training example.

It may fit the training data closely but fail on new houses.

Regularization adds an additional cost when coefficients become large.

---

# 3. Understanding the Regularization Penalty

A normal regression model minimizes prediction error.

For example, using Mean Squared Error:

```text
MSE = Average of squared prediction errors
```

Regularization adds another term to the objective.

```text
New Objective = Prediction Error + Regularization Penalty
```

The model now tries to achieve two things:

1. Make predictions accurate.
2. Avoid unnecessarily large coefficients.

This creates a trade-off.

- Too little penalty: overfitting may remain.
- Appropriate penalty: model complexity may be controlled.
- Too much penalty: useful coefficients may become too small, causing underfitting.

---

# 4. Ridge Regression (L2 Regularization)

Ridge Regression is Linear Regression with an L2 regularization penalty.

It adds a penalty based on the squared values of model coefficients.

### Normal Linear Regression

\[
J(w)=MSE
\]

### Ridge Regression

\[
J(w)=MSE+\lambda\sum_{j=1}^{p}w_j^2
\]

### Understand the Symbols

| Symbol | Meaning |
|---|---|
| J(w) | Objective the model minimizes |
| MSE | Mean Squared Error |
| λ | Regularization strength |
| w | Model weight |
| p | Number of input features |
| w² | Weight multiplied by itself |

The important part is:

\[
\lambda\sum_{j=1}^{p}w_j^2
\]

This is the Ridge penalty.

It calculates the squared value of each weight and adds them together.

### Manual Example

Suppose:

```python
w1 = 2
w2 = 3
w3 = 4
```

Calculate the L2 penalty without lambda:

```text
Penalty = 2² + 3² + 4²

Penalty = 4 + 9 + 16

Penalty = 29
```

If lambda is 0.1:

```text
Regularization penalty = 0.1 × 29

Regularization penalty = 2.9
```

The model must now consider both prediction error and this additional penalty.

### What Happens to Weights?

Ridge generally pushes coefficients toward zero.

Illustrative example:

Before regularization:

```text
w1 = 2.0
w2 = 3.0
w3 = 4.0
```

After regularization:

```text
w1 = 1.7
w2 = 2.5
w3 = 3.2
```

These are illustrative values, not guaranteed results.

IMPORTANT:

Ridge usually makes weights smaller, but generally does not make them exactly zero.

### Python Example

```python
from sklearn.linear_model import Ridge

model = Ridge(alpha=1.0)

model.fit(X_train, y_train)

predictions = model.predict(X_test)

print(model.coef_)
print(model.intercept_)
```

In Scikit-learn, `alpha` controls regularization strength.

A larger `alpha` means a stronger penalty.

---

# 5. Lasso Regression (L1 Regularization)

Lasso is another regularized version of Linear Regression.

It uses the absolute values of coefficients instead of their squares.

### Lasso Objective

\[
J(w)=MSE+\lambda\sum_{j=1}^{p}|w_j|
\]

Compare the penalties:

Ridge:

\[
\lambda\sum w_j^2
\]

Lasso:

\[
\lambda\sum |w_j|
\]

### Manual Example

Suppose:

```python
w1 = 2
w2 = -3
w3 = 4
```

Calculate the L1 penalty:

```text
Penalty = |2| + |-3| + |4|

Penalty = 2 + 3 + 4

Penalty = 9
```

If lambda is 0.1:

```text
Regularization penalty = 0.1 × 9

Regularization penalty = 0.9
```

### What Happens to Weights?

Lasso can push some coefficients exactly to zero.

Illustrative example:

Before:

```text
w1 = 2.0
w2 = 0.5
w3 = 0.02
```

After:

```text
w1 = 1.7
w2 = 0.3
w3 = 0.0
```

The third feature's coefficient becomes zero.

That means the feature does not contribute through its coefficient in the fitted model.

### Why Is This Useful?

Imagine you have 100 input features.

Some may provide little useful information.

Lasso can reduce some coefficients to zero, effectively removing those features from the linear prediction.

This makes Lasso useful for feature selection.

### Python Example

```python
from sklearn.linear_model import Lasso

model = Lasso(alpha=0.1)

model.fit(X_train, y_train)

predictions = model.predict(X_test)

print(model.coef_)
print(model.intercept_)
```

IMPORTANT:

Lasso does not guarantee that it selects the truly important features.

With strongly correlated features, its feature selection can be unstable.

---

# 6. Ridge vs Lasso

This is one of the most important comparisons.

| Ridge (L2) | Lasso (L1) |
|---|---|
| Uses squared coefficients | Uses absolute coefficients |
| Shrinks coefficients toward zero | Shrinks coefficients toward zero |
| Usually keeps coefficients nonzero | Can make coefficients exactly zero |
| Usually retains all features | Can perform feature selection |
| Useful when many features contribute | Useful when a sparse model is desirable |

### Example

Imagine you have five features.

Illustrative results:

| Feature | Ridge | Lasso |
|---|---:|---:|
| Size | 1.8 | 1.9 |
| Bedrooms | 0.7 | 0.6 |
| Age | -0.5 | -0.4 |
| Random feature | 0.02 | 0 |
| Extra feature | 0.01 | 0 |

Ridge reduces small coefficients but generally keeps them.

Lasso can remove some coefficients entirely.

---

# 7. Understanding Lambda — Regularization Strength

Lambda controls how strongly the model penalizes large coefficients.

Imagine three situations.

### 7.1 Very Small Lambda

```python
lambda_value = 0.0001
```

The penalty is weak.

The model behaves more like ordinary Linear Regression.

It may still overfit if the original model is too complex.

### 7.2 Moderate Lambda

```python
lambda_value = 1.0
```

The penalty has a stronger influence.

The model may reduce unnecessarily large coefficients while retaining useful relationships.

### 7.3 Very Large Lambda

```python
lambda_value = 100000
```

The penalty can become extremely strong.

The model may push its coefficients very close to zero.

It may become too simple to represent the relationship between inputs and target.

This can cause underfitting.

### Summary

| Regularization strength | Possible result |
|---|---|
| Too weak | Overfitting may remain |
| Appropriate | Better balance between fit and complexity |
| Too strong | Underfitting |

The goal is not to make lambda as large as possible.

The goal is to find a useful value using validation or cross-validation.

IMPORTANT:

In Scikit-learn, Ridge and Lasso use the parameter name `alpha` for regularization strength. This is commonly called lambda in mathematical explanations.

# 8. Elastic Net Regularization

Elastic Net combines Ridge and Lasso penalties.

It uses both L1 and L2 regularization.

### Objective

\[
J(w)=MSE+
\lambda\left[
\alpha\sum|w_j|
+
\frac{1-\alpha}{2}\sum w_j^2
\right]
\]

Where:

- MSE measures prediction error.
- Lambda controls overall regularization strength.
- Alpha controls the balance between L1 and L2 penalties.

### Important Scikit-Learn Difference

Scikit-learn's `ElasticNet` uses:

- `alpha`: Overall regularization strength.
- `l1_ratio`: Balance between L1 and L2.

Do not confuse these parameter names with the mathematical notation above.

### Understanding l1_ratio

| l1_ratio | Behaviour |
|---:|---|
| 0 | Ridge-like L2 regularization |
| 0.5 | Combination of L1 and L2 |
| 1 | Lasso-like L1 regularization |

### Python Example

```python
from sklearn.linear_model import ElasticNet

model = ElasticNet(
    alpha=0.1,
    l1_ratio=0.5
)

model.fit(X_train, y_train)

predictions = model.predict(X_test)

print(model.coef_)
```

### When Can Elastic Net Be Useful?

- You have many features.
- Some features are correlated.
- You want coefficient shrinkage.
- You also want some coefficients to become zero.

# 9. Why Feature Scaling Matters for Regularization

This is very important.

Remember our house-price features:

```python
size = 2000
bedrooms = 4
age = 10
```

Their numerical scales are different.

Now imagine this regression model:

```text
Prediction =
w1 × size +
w2 × bedrooms +
w3 × age +
b
```

Regularization penalizes coefficient sizes.

But coefficient sizes are affected by the numerical scales of their features.

For example, the model may use a small weight for size because size has large numerical values, while it may use a larger weight for bedrooms.

Comparing those coefficients directly can be misleading.

Regularization may treat differently scaled features unfairly.

### Recommended Approach

For Ridge, Lasso and Elastic Net, numerical features are commonly standardized before fitting.

### Python Example

```python
from sklearn.pipeline import make_pipeline

from sklearn.preprocessing import StandardScaler

from sklearn.linear_model import Ridge

model = make_pipeline(
    StandardScaler(),
    Ridge(alpha=1.0)
)

model.fit(X_train, y_train)

predictions = model.predict(X_test)
```

The pipeline:

1. Learns feature means and standard deviations from training data.
2. Standardizes the training features.
3. Trains Ridge Regression.
4. Applies the same scaling to new data before prediction.

For mixed numerical and categorical data, use a `ColumnTransformer` to preprocess different feature types appropriately.

IMPORTANT:

Do not scale the test data independently.

Learn the scaler from training data and reuse it.

# 10. Choosing the Best Regularization Strength

You should not randomly choose regularization strength.

One common method is cross-validation.

Cross-validation evaluates different parameter values across multiple training and validation splits.

For example, test:

```text
0.001
0.01
0.1
1
10
100
```

Compare their validation performance.

### Python Example: RidgeCV

```python
from sklearn.linear_model import RidgeCV

from sklearn.pipeline import make_pipeline

from sklearn.preprocessing import StandardScaler

alphas = [
    0.001,
    0.01,
    0.1,
    1,
    10,
    100
]

model = make_pipeline(
    StandardScaler(),
    RidgeCV(alphas=alphas)
)

model.fit(X_train, y_train)

print(
    model.named_steps["ridgecv"].alpha_
)
```

This example uses Ridge's built-in cross-validation to select an alpha value.

### Python Example: GridSearchCV

```python
from sklearn.model_selection import GridSearchCV

from sklearn.pipeline import Pipeline

from sklearn.preprocessing import StandardScaler

from sklearn.linear_model import Ridge


pipeline = Pipeline([
    ("scaler", StandardScaler()),
    ("model", Ridge())
])


parameters = {
    "model__alpha": [
        0.001,
        0.01,
        0.1,
        1,
        10,
        100
    ]
}


search = GridSearchCV(
    pipeline,
    parameters,
    cv=5,
    scoring="neg_mean_squared_error"
)


search.fit(X_train, y_train)


print("Best parameters:", search.best_params_)

print("Best CV score:", search.best_score_)
```

The pipeline ensures scaling is learned separately inside each cross-validation training fold.

For time-series problems, ordinary random cross-validation may be inappropriate.

Use time-aware validation such as `TimeSeriesSplit`.

# 11. Comparing Linear, Ridge, Lasso and Elastic Net

You can train multiple models and compare their performance.

```python
from sklearn.linear_model import (
    LinearRegression,
    Ridge,
    Lasso,
    ElasticNet
)

from sklearn.pipeline import make_pipeline

from sklearn.preprocessing import StandardScaler

from sklearn.metrics import mean_squared_error


models = {
    "Linear": LinearRegression(),

    "Ridge": Ridge(alpha=1.0),

    "Lasso": Lasso(alpha=0.1),

    "ElasticNet": ElasticNet(
        alpha=0.1,
        l1_ratio=0.5
    )
}


for name, estimator in models.items():

    model = make_pipeline(
        StandardScaler(),
        estimator
    )

    model.fit(X_train, y_train)

    predictions = model.predict(X_test)

    mse = mean_squared_error(
        y_test,
        predictions
    )

    rmse = mse ** 0.5

    print(name, "RMSE:", rmse)
```

This example assumes the training and test datasets are already prepared numerical datasets.

For a fair comparison:

- Use the same data splits.
- Use the same evaluation metric.
- Tune each model using training data and validation or cross-validation.
- Keep the final test set separate.

The model with the lowest training error is not automatically the best model.

# 12. Regularization and Overfitting

Let's compare two models.

| Metric | Model A | Model B |
|---|---:|---:|
| Training RMSE | 2.0 | 4.0 |
| Validation RMSE | 9.0 | 5.0 |

Model A:

- Very low training error.
- High validation error.

This may indicate overfitting.

Model B:

- Higher training error.
- Lower validation error.

Model B performs better on the validation data.

Regularization can sometimes create this improvement by reducing model complexity.

However, regularization is not always beneficial.

If a model is already too simple, adding a strong penalty can make it worse.

---

# 13. Important Limitations of Regularization

Regularization is useful, but it has limitations.

### A. It Can Cause Underfitting

A very strong penalty can shrink useful coefficients too much.

### B. It Does Not Fix Every Problem

Regularization does not automatically fix:

- Missing values.
- Incorrect data.
- Data leakage.
- Poor feature engineering.
- Nonlinear relationships that the model cannot represent.

### C. Lasso Can Be Unstable With Correlated Features

If two features contain similar information, Lasso may choose one and set the other's coefficient to zero.

The selected feature may change when the training data changes.

### D. Feature Scaling Is Important

Different feature scales can make regularization behave poorly.

### E. Regularization Does Not Guarantee Better Predictions

Always evaluate using validation data and keep the final test set separate.

---

# 14. When Should You Use Each Method?

| Method | When it may be useful |
|---|---|
| Linear Regression | Baseline model without regularization |
| Ridge | Many features contribute and coefficient shrinkage is useful |
| Lasso | You want a sparse model with some coefficients set to zero |
| Elastic Net | You want both L1 and L2 penalties, especially with correlated features |

These are general guidelines, not strict rules.

Compare models on your actual problem.

# 16. Final Understanding

Regularization changes how a regression model learns.

Ordinary Linear Regression focuses on minimizing prediction error.

Regularized regression minimizes prediction error while also penalizing large coefficients.

Remember the three important methods:

1. **Ridge:** Shrinks coefficients toward zero.
2. **Lasso:** Can shrink some coefficients exactly to zero.
3. **Elastic Net:** Combines Ridge and Lasso.

The most important practical skills are:

- Understanding the difference between L1 and L2.
- Knowing when to use Ridge, Lasso or Elastic Net.
- Scaling features correctly.
- Selecting regularization strength using cross-validation.
- Comparing models using validation performance.
- Keeping the final test set separate.
