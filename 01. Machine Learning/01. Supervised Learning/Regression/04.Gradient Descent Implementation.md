 
# Gradient Descent Implementation

# 1. Introduction

Gradient Descent is an optimization algorithm used to train machine learning models.

Its purpose is to find suitable values for the model's weights and bias so that the model produces smaller prediction errors.

In this document, we will implement Gradient Descent from scratch using Python.

We will not initially depend on machine learning libraries to calculate gradients or update model parameters.

We will manually implement:

1. Dataset preparation.
2. Model initialization.
3. Forward propagation.
4. Prediction calculation.
5. Error calculation.
6. Loss calculation.
7. Gradient calculation.
8. Weight and bias updates.
9. Training loops.
10. Convergence monitoring.
11. Model evaluation.
12. Predictions on new data.

We will implement three training approaches:

- Batch Gradient Descent.
- Stochastic Gradient Descent.
- Mini-Batch Gradient Descent.

# PART 2: FORWARD PROPAGATION

# 5. What Is Forward Propagation?

Forward propagation means passing input data through the model to calculate predictions.

In our house-price model:

1. Give the model house size.
2. Give the model the number of bedrooms.
3. Give the model house age.
4. The model multiplies each feature by its corresponding weight.
5. It adds the bias.
6. It produces a predicted house price.

Example:

```python
Size = 1000

Bedrooms = 2

Age = 10

prediction = (
    w1 * Size +
    w2 * Bedrooms +
    w3 * Age +
    b
)
```

If all parameters are initially zero:

```python
w1 = 0.0
w2 = 0.0
w3 = 0.0
b = 0.0
```

Then:

```text
Prediction = 0
```

The model initially predicts zero because every parameter is zero.

After training updates the parameters, its predictions will change.

### Important

Forward propagation calculates predictions.

It does not update the weights.

# PART 3: ERROR AND LOSS CALCULATION

# 7. Calculate Prediction Errors

A prediction error measures the difference between the actual value and the predicted value.

We use:

Error = Actual - Prediction

Python:

```python
error = actual - prediction
```

Example:

| House | Actual | Prediction | Error |
|---|---:|---:|---:|
| 1 | 20 | 0 | 20 |
| 2 | 30 | 0 | 30 |
| 3 | 40 | 0 | 40 |
| 4 | 50 | 0 | 50 |

Our model has made four errors.

### Important

An individual error belongs to one training example.

It is not the same as the overall loss of the model.

---

# 8. What Is a Loss Function?

A loss function measures how wrong the model's predictions are.

For our implementation, we will use Mean Squared Error (MSE).

MSE:

1. Calculates individual errors.
2. Squares each error.
3. Adds the squared errors.
4. Divides by the number of examples.

Formula:

MSE = Sum of Squared Errors / Number of Examples

Example:

| House | Error | Squared error |
|---|---:|---:|
| 1 | 20 | 400 |
| 2 | 30 | 900 |
| 3 | 40 | 1600 |
| 4 | 50 | 2500 |

Total squared error:

```text
400 + 900 + 1600 + 2500 = 5400
```

MSE:

```text
5400 / 4 = 1350
```

The initial loss is:

```text
MSE = 1350
```

### Python implementation

```python
total_loss = 0.0

for Size, Bedrooms, Age, actual in zip(
    size, bedrooms, age, y
):

    prediction = (
        w1 * Size +
        w2 * Bedrooms +
        w3 * Age +
        b
    )

    error = actual - prediction

    total_loss += error ** 2


mse = total_loss / n

print("MSE:", mse)
```

Output:

```text
MSE: 1350.0
```

**Important:** Loss measures overall prediction error. Gradient Descent uses gradients of this loss function to update parameters.

# PART 4: GRADIENT CALCULATION

# 9. What Is a Gradient?

A gradient tells us how the loss changes when a model parameter changes.

Our model has four parameters:

- w1
- w2
- w3
- b

Each parameter has its own gradient.

For example:

- `w1_gradient` tells us how loss changes when `w1` changes.
- `w2_gradient` tells us how loss changes when `w2` changes.
- `w3_gradient` tells us how loss changes when `w3` changes.
- `b_gradient` tells us how loss changes when bias changes.

The gradients help Gradient Descent decide how to update the model.

---

# 10. Deriving the MSE Gradients

Our prediction equation:

Prediction = w1 × Size + w2 × Bedrooms + w3 × Age + b

Our error convention:

Error = Actual - Prediction

Our loss:

MSE = Average of (Actual - Prediction)²

The gradient for each parameter is:

Size gradient:

```text
-(2/n) × Sum(error × Size)
```

Bedrooms gradient:

```text
-(2/n) × Sum(error × Bedrooms)
```

Age gradient:

```text
-(2/n) × Sum(error × Age)
```

Bias gradient:

```text
-(2/n) × Sum(error)
```

### Why is there a negative sign?

Our error is defined as:

```python
error = actual - prediction
```

The derivative of squared error with respect to prediction introduces a negative sign.

Therefore, the gradients have the negative sign shown above.

**Important:** These gradient formulas are consistent with our error convention. If we instead define error as `prediction - actual`, the gradient signs change.

---

# 11. Understanding Gradient Accumulation

Before calculating the overall gradients, we collect information from training examples.

We initialize four accumulators:

```python
sum_size_blame = 0.0

sum_bedrooms_blame = 0.0

sum_age_blame = 0.0

sum_overall_blame = 0.0
```

For every house:

```python
sum_size_blame += error * Size

sum_bedrooms_blame += error * Bedrooms

sum_age_blame += error * Age

sum_overall_blame += error
```

Each house contributes information to the accumulators.

After processing the required training examples, we calculate the gradients.

### Why accumulate?

Because the model needs the combined gradient information from the training examples being used for that update.

---

# PART 5: WEIGHT UPDATES

# 12. Understanding the Weight Update Formula

Gradient Descent updates parameters using:

New Weight = Old Weight - (Learning Rate × Gradient)

For our model:

```python
w1 = w1 - (lr * size_grad)

w2 = w2 - (lr * bedrooms_grad)

w3 = w3 - (lr * age_grad)

b = b - (lr * b_gradient)
```

### Understanding the operation

- Old weight = Current parameter value.
- Learning rate = Controls update size.
- Gradient = Direction and rate of loss change.
- New weight = Updated parameter value.

The model uses the gradients to move toward lower loss.

### Important

Calculating gradients and updating weights are two different operations.

1. Gradient calculation tells us how the loss changes.
2. Parameter updates change the model's weights and bias.

# PART 6: COMPLETE BATCH GRADIENT DESCENT

# 13. Implement Batch Gradient Descent From Scratch

Batch Gradient Descent processes the entire dataset before updating parameters.

Complete implementation:

```python
# Dataset

size = [1000, 1500, 2000, 2500]

bedrooms = [2, 3, 3, 4]

age = [10, 8, 5, 2]

y = [20, 30, 40, 50]

n = len(y)


# Initialize parameters

w1 = 0.0

w2 = 0.0

w3 = 0.0

b = 0.0


# Learning rate

lr = 0.0000001


# Training

for epoch in range(1000):

    # Reset gradient accumulators

    sum_size_blame = 0.0

    sum_bedrooms_blame = 0.0

    sum_age_blame = 0.0

    sum_overall_blame = 0.0

    total_loss = 0.0


    # Process the entire dataset

    for Size, Bedrooms, Age, actual in zip(
        size, bedrooms, age, y
    ):

        # Prediction

        prediction = (
            w1 * Size +
            w2 * Bedrooms +
            w3 * Age +
            b
        )

        # Error

        error = actual - prediction

        # Calculate squared error

        total_loss += error ** 2

        # Accumulate gradient information

        sum_size_blame += error * Size

        sum_bedrooms_blame += error * Bedrooms

        sum_age_blame += error * Age

        sum_overall_blame += error


    # Calculate loss

    loss = total_loss / n


    # Calculate gradients

    size_grad = -(2 / n) * sum_size_blame

    bedrooms_grad = -(2 / n) * sum_bedrooms_blame

    age_grad = -(2 / n) * sum_age_blame

    b_gradient = -(2 / n) * sum_overall_blame


    # Update parameters once

    w1 = w1 - (lr * size_grad)

    w2 = w2 - (lr * bedrooms_grad)

    w3 = w3 - (lr * age_grad)

    b = b - (lr * b_gradient)


    print(
        f"Epoch {epoch + 1}, Loss: {loss:.4f}"
    )
```

### Understand the loop structure

```python
for epoch in range(1000):
```

This repeats training for 1,000 epochs.

```python
for Size, Bedrooms, Age, actual in zip(
    size, bedrooms, age, y
):
```

This processes all training examples.

The parameter updates happen outside the inner loop.

Therefore:

One complete dataset pass produces one weight update.

# PART 7: STOCHASTIC GRADIENT DESCENT

# 14. Implement SGD From Scratch

SGD processes one training example and updates the parameters immediately.

```python
# Dataset

size = [1000, 1500, 2000, 2500]

bedrooms = [2, 3, 3, 4]

age = [10, 8, 5, 2]

y = [20, 30, 40, 50]


# Initialize parameters

w1 = 0.0

w2 = 0.0

w3 = 0.0

b = 0.0


lr = 0.0000001


# Training

for epoch in range(1000):

    for Size, Bedrooms, Age, actual in zip(
        size, bedrooms, age, y
    ):

        # Prediction

        prediction = (
            w1 * Size +
            w2 * Bedrooms +
            w3 * Age +
            b
        )

        # Error

        error = actual - prediction


        # Gradients from one training example

        size_grad = -2 * error * Size

        bedrooms_grad = -2 * error * Bedrooms

        age_grad = -2 * error * Age

        b_gradient = -2 * error


        # Update immediately

        w1 = w1 - (lr * size_grad)

        w2 = w2 - (lr * bedrooms_grad)

        w3 = w3 - (lr * age_grad)

        b = b - (lr * b_gradient)
```

### Important difference

The parameter updates happen inside the inner loop.

This means every individual training example produces an update.

For four examples:

```text
House 1 → Update 1

House 2 → Update 2

House 3 → Update 3

House 4 → Update 4
```

There are four updates per epoch.

# PART 8: MINI-BATCH GRADIENT DESCENT

# 15. Implement Mini-Batch Gradient Descent From Scratch

Mini-Batch Gradient Descent processes a small group of examples before updating parameters.

Example:

```python
batch_size = 2
```

For four training examples:

```text
Batch 1: Houses 1 and 2

Batch 2: Houses 3 and 4
```

Each batch produces one parameter update.

### Complete implementation

```python
# Dataset

size = [1000, 1500, 2000, 2500]

bedrooms = [2, 3, 3, 4]

age = [10, 8, 5, 2]

y = [20, 30, 40, 50]


# Training settings

batch_size = 2

epochs = 1000

lr = 0.0000001


# Initialize parameters

w1 = 0.0

w2 = 0.0

w3 = 0.0

b = 0.0


# Training

for epoch in range(epochs):

    total_loss = 0.0


    # Move through the dataset batch by batch

    for start in range(0, len(y), batch_size):

        end = start + batch_size


        # Extract the current batch

        batch_size_data = size[start:end]

        batch_bedrooms = bedrooms[start:end]

        batch_age = age[start:end]

        batch_y = y[start:end]


        # Reset accumulators for the current batch

        sum_size_blame = 0.0

        sum_bedrooms_blame = 0.0

        sum_age_blame = 0.0

        sum_overall_blame = 0.0


        # Process examples in the current batch

        for Size, Bedrooms, Age, actual in zip(
            batch_size_data,
            batch_bedrooms,
            batch_age,
            batch_y
        ):

            # Prediction

            prediction = (
                w1 * Size +
                w2 * Bedrooms +
                w3 * Age +
                b
            )

            # Error

            error = actual - prediction

            # Record squared error

            total_loss += error ** 2

            # Accumulate gradients

            sum_size_blame += error * Size

            sum_bedrooms_blame += error * Bedrooms

            sum_age_blame += error * Age

            sum_overall_blame += error


        # Number of examples in this batch

        current_batch_size = len(batch_y)


        # Calculate gradients

        size_grad = -(2 / current_batch_size) * sum_size_blame

        bedrooms_grad = -(2 / current_batch_size) * sum_bedrooms_blame

        age_grad = -(2 / current_batch_size) * sum_age_blame

        b_gradient = -(2 / current_batch_size) * sum_overall_blame


        # Update parameters once per batch

        w1 = w1 - (lr * size_grad)

        w2 = w2 - (lr * bedrooms_grad)

        w3 = w3 - (lr * age_grad)

        b = b - (lr * b_gradient)


    # Calculate average loss observed during the epoch

    epoch_loss = total_loss / len(y)

    print(
        f"Epoch {epoch + 1}, Loss: {epoch_loss:.4f}"
    )
```

### Important

The accumulated gradients are reset for each batch.

The weights are updated after all examples in the current batch have been processed.

The next batch uses the newly updated weights.

# PART 9: EVALUATING THE MODEL

# 16. Evaluate the Model After Training

After training, we need to evaluate the final model.

We should not assume that completing the training loop means the model is accurate.

Let's calculate predictions using the final weights.

```python
predictions = []

for Size, Bedrooms, Age in zip(
    size, bedrooms, age
):

    prediction = (
        w1 * Size +
        w2 * Bedrooms +
        w3 * Age +
        b
    )

    predictions.append(prediction)


print("Predictions:", predictions)
```

### Calculate final MSE

```python
total_loss = 0.0

for actual, prediction in zip(y, predictions):

    error = actual - prediction

    total_loss += error ** 2


final_mse = total_loss / len(y)

print("Final MSE:", final_mse)
```

This calculates the loss of the final trained model on the training dataset.

### Why calculate it separately?

During mini-batch training, the model's weights change after each batch.

Therefore, a loss accumulated while processing batches does not necessarily represent the loss of the final weights.

A separate evaluation pass solves this problem.

# 20. Detect Small Loss Improvements

One possible stopping condition checks whether the loss improvement becomes very small.

```python
threshold = 0.0001

patience = 5

small_improvement_count = 0

previous_loss = None
```

After calculating the current epoch loss:

```python
if previous_loss is not None:

    improvement = previous_loss - epoch_loss

    if 0 <= improvement < threshold:

        small_improvement_count += 1

    else:

        small_improvement_count = 0


    if small_improvement_count >= patience:

        print("Convergence may have been reached")

        break


previous_loss = epoch_loss
```

### Understanding this process

1. Calculate current loss.
2. Compare it with previous loss.
3. Calculate improvement.
4. Check whether improvement is smaller than the threshold.
5. Count consecutive small improvements.
6. Stop when the patience limit is reached.

This is a practical stopping rule, not mathematical proof of reaching a global minimum.

# PART 11: DEBUGGING AND COMMON MISTAKES

# 21. Common Implementation Mistakes

### Mistake 1: Updating weights inside the wrong loop

In Batch Gradient Descent, weights must be updated after processing the entire dataset.

In SGD, weights are updated after each individual example.

In Mini-Batch Gradient Descent, weights are updated after each batch.

### Mistake 2: Forgetting to reset gradient accumulators

Incorrect:

```python
for batch in batches:

    # Accumulators continue from previous batch
```

Correct:

```python
for batch in batches:

    sum_size_blame = 0.0

    sum_bedrooms_blame = 0.0

    sum_age_blame = 0.0

    sum_overall_blame = 0.0
```

### Mistake 3: Using the wrong denominator

For full-batch MSE gradients:

```python
-(2 / dataset_size) * accumulated_gradient
```

For mini-batch MSE gradients:

```python
-(2 / current_batch_size) * accumulated_gradient
```

For a single-example SGD update:

```python
-2 * error * feature
```

### Mistake 4: Incorrect error convention

If using:

```python
error = actual - prediction
```

The gradient formulas must include the negative sign.

If using:

```python
error = prediction - actual
```

The gradient formulas have the opposite sign.

Do not mix the two conventions.

### Mistake 5: Updating parameters before completing a mini-batch

In Mini-Batch Gradient Descent, calculate the combined gradient first.

Then update parameters.

### Mistake 6: Forgetting to evaluate the final model

Always calculate predictions and loss using the final trained parameters.

### Mistake 7: Choosing a learning rate without considering feature scales

Our house-size values are much larger than bedroom counts.

This can cause very different gradient magnitudes for different weights.

Feature scaling can help make optimization more manageable.

### Mistake 8: Confusing training loss with validation loss

Training loss measures performance on training data.

Validation loss measures performance on separate validation data.

Both are useful, but they answer different questions.

# PART 13: ADVANCED PRACTICAL UNDERSTANDING

# 23. Training Loss vs Evaluation Loss

A loss calculated during training is not always the same as the final loss of the model after all updates.

For example, in SGD:

1. Process House 1 using the initial weights.
2. Update weights.
3. Process House 2 using updated weights.
4. Update weights again.
5. Continue.

The errors are calculated using different parameter values.

Therefore, the average of those training-time errors is not exactly the loss of the final model.

To measure final training performance correctly:

1. Finish all parameter updates for the epoch.
2. Use the final weights.
3. Run predictions on the training dataset.
4. Calculate MSE without updating parameters.

This provides a consistent evaluation.

# 24. Training Data vs Validation Data vs Test Data

Real machine learning projects normally divide available data into separate groups.

### Training data

Used to learn model parameters.

### Validation data

Used to compare models, tune hyperparameters and monitor generalization during development.

### Test data

Used for final evaluation after model development decisions are complete.

Example:

```text
Complete Dataset
      |
      v
Training Dataset
      |
      v
Validation Dataset
      |
      v
Test Dataset
```

For time-series datasets, splits must respect chronological order.

Randomly mixing future and past observations can create data leakage.
