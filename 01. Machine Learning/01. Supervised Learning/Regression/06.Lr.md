
# AI/ML – Learning Rate: Complete Study Notes

# 1. What Is Learning Rate?

Learning Rate (LR) is a value that controls how much a model's parameters change during training.

A machine learning model learns by adjusting its weights and bias.

During training:

1. The model makes a prediction.
2. We compare the prediction with the actual answer.
3. We calculate the loss.
4. We calculate gradients.
5. We update the model's weights and bias.

Learning rate controls the size of those updates.

## 1.1 Basic weight update

The general weight update formula is:

```python
new_weight = old_weight - (lr * gradient)
```

Let's understand each value:

- `old_weight`: Current weight.
- `lr`: Learning rate.
- `gradient`: Information about how the loss changes when the weight changes.
- `new_weight`: Updated weight.

The learning rate controls how strongly the gradient affects the weight update.

## 1.2 Numerical example

Suppose:

```python
weight = 10.0
gradient = 4.0
lr = 0.01
```

Weight update:

```python
new_weight = 10.0 - (0.01 * 4.0)
```

Result:

```text
new_weight = 9.96
```

Now change only the learning rate:

```python
weight = 10.0
gradient = 4.0
lr = 0.5
```

Result:

```text
new_weight = 8.0
```

Compare:

| Learning rate | Weight update | New weight |
|---|---:|---:|
| 0.01 | -0.04 | 9.96 |
| 0.5 | -2.00 | 8.00 |
| 1.0 | -4.00 | 6.00 |

A larger learning rate produces a larger update when the gradient stays the same.

Important:

Learning rate does not directly decide the weight's new value.

The actual update depends on BOTH the learning rate and the gradient.

# 2. Why Is Learning Rate Important?

Imagine that your model is trying to find the correct weights to predict house prices.

Initially, the weights may be far from their useful values.

The model needs to adjust them.

There are three important possibilities.

## 2.1 Learning rate is too small

Suppose the learning rate is extremely small.

```python
lr = 0.00000001
```

The model makes very tiny updates.

For example, imagine its loss decreases like this:

| Epoch | Loss |
|---|---:|
| 1 | 100 |
| 2 | 99.9 |
| 3 | 99.8 |
| 4 | 99.7 |
| 5 | 99.6 |

The loss is improving, but very slowly.

Possible problems:

- Training takes a long time.
- The model may need many more epochs.
- It may not reach a good solution within the available training time.

Important:

A small learning rate does not automatically mean the model is bad.

It may simply require more training.

## 2.2 Learning rate is too large

Suppose:

```python
lr = 5.0
```

The model makes extremely large updates.

It may repeatedly jump across a good solution instead of approaching it.

For example, imagine loss behaves like this:

| Epoch | Loss |
|---|---:|
| 1 | 100 |
| 2 | 180 |
| 3 | 90 |
| 4 | 250 |
| 5 | 400 |

The loss is unstable and increasing.

Possible problems:

- Training becomes unstable.
- Loss may oscillate.
- The model may fail to converge.
- The loss may become extremely large or even produce numerical errors.

A very large learning rate can prevent the model from learning properly.

## 2.3 Learning rate is suitable

A suitable learning rate allows the model to make useful progress without excessively large updates.

Example:

| Epoch | Loss |
|---|---:|
| 1 | 100 |
| 2 | 80 |
| 3 | 60 |
| 4 | 45 |
| 5 | 35 |
| 6 | 28 |

The loss decreases steadily.

This is a possible sign of stable training.

However, the training loss alone does not prove that the model generalizes well.

We also need to evaluate performance on validation data.

# 3. What Is the Relationship Between Gradient and Learning Rate?

This is one of the most important concepts.

Consider:

```python
new_weight = old_weight - (lr * gradient)
```

The gradient and learning rate work together.

Let's compare three situations.

### Situation A: Small gradient

```python
gradient = 0.1
lr = 0.01
```

Update amount:

```text
0.001
```

### Situation B: Large gradient

```python
gradient = 100
lr = 0.01
```

Update amount:

```text
1.0
```

### Situation C: Same large gradient, smaller LR

```python
gradient = 100
lr = 0.0001
```

Update amount:

```text
0.01
```

Notice:

Even when the learning rate stays the same, different gradient magnitudes produce different update sizes.

This is why selecting a learning rate cannot be done by looking at the learning-rate value alone.

## 3.1 Important: Feature scaling affects learning rate

Consider your house-price dataset:

```python
size = [1000, 1500, 2000, 2500]

bedrooms = [2, 3, 3, 4]

age = [10, 8, 5, 2]
```

The features have different numerical scales.

- House size: 1000 to 2500.
- Bedrooms: 2 to 4.
- Age: 2 to 10.

Suppose the gradients are:

```python
Size_grad = 100000
Bedrooms_grad = 20
Age_grad = 50
```

With:

```python
lr = 0.000001
```

The update amounts are:

```text
Size update     = 0.1
Bedrooms update = 0.00002
Age update      = 0.00005
```

The size weight receives a much larger update.

This happens because its gradient is much larger.

Feature scaling can help bring features to more comparable numerical ranges.

Common scaling methods include:

- Standardization
- Min-Max Scaling

This is especially important in many gradient-based machine learning algorithms.

# 4. How Do We Choose a Suitable Learning Rate?

There is no single learning rate that works best for every dataset and model.

The correct value depends on:

- Dataset.
- Feature scales.
- Model architecture.
- Loss function.
- Training method.
- Gradient magnitudes.

A practical approach is to experiment with several candidate values.

## 4.1 Learning rate experiments

For example:

```python
learning_rates = [
    0.1,
    0.01,
    0.001,
    0.0001,
    0.00001
]
```

Train the same model using each candidate learning rate.

Record the training and validation loss.

Example:

| Learning rate | Training result |
|---|---|
| 0.1 | Unstable |
| 0.01 | Stable |
| 0.001 | Stable but slower |
| 0.0001 | Very slow |
| 0.00001 | Extremely slow |

In this hypothetical example, 0.01 may be a reasonable starting choice.

But we must also check validation performance.

## 4.2 Python example

```python
learning_rates = [
    0.1,
    0.01,
    0.001,
    0.0001,
    0.00001
]

for lr in learning_rates:

    # Reset weights for a fair experiment
    w1 = 0.0
    w2 = 0.0
    w3 = 0.0
    b = 0.0

    # Train the model using this LR
    for epoch in range(1000):

        # Prediction
        # Calculate error
        # Calculate gradients
        # Update weights

        pass

    # Evaluate the trained model
    print("Learning rate:", lr)
```

Important:

Every candidate should start from the same initial weights.

Otherwise, the comparison may not be fair.

For a rigorous comparison, keep the training and validation split, preprocessing, number of epochs and other settings consistent.

# 5. What Is a Learning Rate Finder?

A Learning Rate Finder is a technique for identifying a useful starting learning rate.

Instead of choosing a random value, we gradually increase the learning rate during a short training experiment.

We record the loss at each learning rate.

Example:

| Learning rate | Loss |
|---|---:|
| 0.00001 | 100 |
| 0.0001 | 80 |
| 0.001 | 45 |
| 0.01 | 20 |
| 0.1 | 35 |
| 1.0 | 500 |

Interpretation:

- At very small LR, the model learns slowly.
- As LR increases, loss improves.
- At some point, the loss starts increasing.
- A learning rate near the region of rapid improvement may be a useful candidate.

Usually, we avoid selecting a value right at the unstable region.

The exact selection depends on the curve and the training problem.

## 5.1 When is a Learning Rate Finder useful?

- When starting a new neural network project.
- When the dataset has unfamiliar feature scales.
- When manually choosing an initial learning rate is difficult.
- When experimenting with a new model architecture.

# 6. Learning Rate Scheduling

A Learning Rate Scheduler changes the learning rate during training according to a defined strategy.

Why do we need this?

Imagine that the model starts training with:

```python
lr = 0.01
```

At the beginning, relatively large updates may help it make progress.

Later, when the model approaches a good solution, smaller updates may help it refine its parameters.

A scheduler controls how the learning rate changes over time.

The four important scheduling methods are:

1. Step Decay
2. Exponential Decay
3. Cosine Annealing
4. ReduceLROnPlateau

---

# 7. Step Decay

## 7.1 What is Step Decay?

Step Decay reduces the learning rate after a fixed number of epochs.

For example:

```python
lr = 0.02
```

Rule:

Reduce the learning rate by half every 50 epochs.

The learning rate becomes:

| Epoch | Learning rate |
|---|---:|
| 1–50 | 0.020 |
| 51–100 | 0.010 |
| 101–150 | 0.005 |
| 151–200 | 0.0025 |
| 201–250 | 0.00125 |

The learning rate remains constant within each interval and drops at the scheduled boundaries.

## 7.2 Python implementation

```python
lr = 0.02

for epoch in range(250):

    # Prediction
    # Calculate loss
    # Calculate gradients

    # Update weights
    w1 -= lr * Size_grad
    w2 -= lr * Bedrooms_grad
    w3 -= lr * Age_grad
    b -= lr * B_gradient

    # Reduce LR every 50 epochs
    if (epoch + 1) % 50 == 0:

        lr = lr * 0.5

    print("Epoch:", epoch + 1, "LR:", lr)
```

Explanation:

```python
(epoch + 1) % 50 == 0
```

Checks whether the completed epoch is divisible by 50.

Therefore, the learning rate is reduced after epochs:

- 50
- 100
- 150
- 200

The new learning rate is used in the following epoch.

## 7.3 Advantages

- Easy to understand.
- Easy to implement.
- Gives predictable learning-rate changes.
- Useful when the training duration is known.

## 7.4 Disadvantages

- Reduction happens at predetermined times.
- It does not check whether the model actually needs a reduction.
- A poorly selected interval may reduce LR too early or too late.

## 7.5 Where is Step Decay used?

- CNN training.
- Computer vision.
- Traditional deep learning experiments.
- Training setups where the epoch schedule is known in advance.

---

# 8. Exponential Decay

## 8.1 What is Exponential Decay?

Exponential Decay reduces the learning rate gradually using an exponential function.

Unlike Step Decay, it does not wait for fixed intervals to make sudden drops.

A common formula is:

```text
lr = initial_lr * decay_rate ** step
```

Where:

- `initial_lr`: Starting learning rate.
- `decay_rate`: Controls how quickly LR decreases.
- `step`: Number of decay steps.

## 8.2 Example

```python
initial_lr = 0.1
decay_rate = 0.9
```

If we reduce the learning rate by 10% at each step:

| Step | Learning rate |
|---|---:|
| 0 | 0.10000 |
| 1 | 0.09000 |
| 2 | 0.08100 |
| 3 | 0.07290 |
| 4 | 0.06561 |
| 5 | 0.05905 |

Notice:

Each new value is 90% of the previous value.

This is exponential decay.

## 8.3 Python implementation

```python
initial_lr = 0.1
decay_rate = 0.9

for epoch in range(100):

    lr = initial_lr * (decay_rate ** epoch)

    # Prediction
    # Calculate loss
    # Calculate gradients

    # Update weights
    w1 -= lr * Size_grad
    w2 -= lr * Bedrooms_grad
    w3 -= lr * Age_grad
    b -= lr * B_gradient
```

Here:

```python
decay_rate ** epoch
```

controls how much the learning rate has decayed.

## 8.4 Advantages

- Smooth learning-rate reduction.
- Simple mathematical formula.
- Does not require sudden drops.
- Useful when gradual reduction is preferred.

## 8.5 Disadvantages

- The learning rate may become too small.
- Decay speed must be selected carefully.
- It follows a predetermined schedule rather than reacting to actual model performance.

## 8.6 Where is Exponential Decay used?

- Neural network training.
- Deep learning experiments.
- Models where a smooth reduction is useful.
- Training processes with a known duration.

---

# 9. Cosine Annealing

## 9.1 What is Cosine Annealing?

Cosine Annealing reduces the learning rate according to a cosine-shaped curve.

It usually starts at a maximum learning rate and gradually moves toward a minimum learning rate.

Example:

```python
initial_lr = 0.1
minimum_lr = 0.001
```

The learning rate decreases smoothly throughout the schedule.

Unlike Step Decay, it does not suddenly drop.

Unlike ordinary exponential decay, its reduction follows a cosine-shaped curve.

## 9.2 How does it behave?

Imagine the training process:

- Beginning: Learning rate is relatively high.
- Middle: Learning rate has decreased.
- End: Learning rate approaches its minimum.

## 9.3 Mathematical formula

```text
lr = min_lr + 0.5 * (max_lr - min_lr)
     * (1 + cos(pi * progress))
```

Where:

- `min_lr`: Minimum learning rate.
- `max_lr`: Maximum learning rate.
- `progress`: Training progress between 0 and 1.
- `cos`: Cosine mathematical function.
- `pi`: Mathematical constant.

## 9.4 Python implementation

```python
import math

max_lr = 0.1
min_lr = 0.001

total_epochs = 100

for epoch in range(total_epochs):

    progress = epoch / total_epochs

    lr = min_lr + 0.5 * (max_lr - min_lr) * (
        1 + math.cos(math.pi * progress)
    )

    # Prediction
    # Calculate loss
    # Calculate gradients

    # Update weights
    w1 -= lr * Size_grad
    w2 -= lr * Bedrooms_grad
    w3 -= lr * Age_grad
    b -= lr * B_gradient
```

This example uses a single cosine decay from the maximum toward the minimum.

## 9.5 Advantages

- Smooth reduction.
- Does not require sudden learning-rate drops.
- Useful in modern neural-network training.
- Can be combined with warm-up.

## 9.6 Disadvantages

- Requires a planned schedule length.
- If training duration changes significantly, the schedule may need adjustment.
- The cosine schedule does not automatically know whether validation performance is improving.

## 9.7 Where is Cosine Annealing used?

- CNNs.
- Image classification.
- Transformers.
- Modern deep learning.
- Large-scale neural-network training.

---

# 10. ReduceLROnPlateau

## 10.1 What is ReduceLROnPlateau?

ReduceLROnPlateau reduces the learning rate when a monitored metric stops improving.

Unlike Step Decay, it does not depend on a fixed epoch interval.

It checks the model's performance.

For example:

| Epoch | Validation loss |
|---|---:|
| 1 | 100 |
| 2 | 80 |
| 3 | 60 |
| 4 | 40 |
| 5 | 40 |
| 6 | 40 |
| 7 | 40 |

The validation loss stopped improving.

The scheduler can reduce the learning rate.

## 10.2 What is Patience?

Patience determines how many consecutive epochs the scheduler waits without improvement before reducing LR.

For example:

```python
patience = 3
```

If the monitored loss fails to improve for three consecutive epochs, the scheduler reduces the learning rate.

## 10.3 What is Factor?

Factor determines how much the learning rate is reduced.

For example:

```python
factor = 0.5
```

If:

```python
lr = 0.02
```

After reduction:

```python
lr = 0.01
```

Because:

```text
0.02 * 0.5 = 0.01
```

## 10.4 Python implementation

```python
lr = 0.02

patience = 3
factor = 0.5

best_loss = float("inf")
epochs_without_improvement = 0

for epoch in range(100):

    # Train the model
    # Calculate training loss

    validation_loss = 50  # Example placeholder

    if validation_loss < best_loss:

        best_loss = validation_loss
        epochs_without_improvement = 0

    else:

        epochs_without_improvement += 1

    # Check patience
    if epochs_without_improvement >= patience:

        lr = lr * factor

        epochs_without_improvement = 0
```

This is a simplified educational implementation.

A production implementation should also handle minimum learning rates, improvement thresholds, checkpointing and the validation metric's numerical precision.

## 10.5 Advantages

- Reacts to actual model performance.
- Does not require a fixed reduction epoch.
- Useful when it is difficult to predict when progress will slow down.

## 10.6 Disadvantages

- Depends on the monitored metric.
- Validation loss may be noisy.
- Patience and reduction factor require tuning.
- It may reduce LR too early if the validation metric fluctuates.

## 10.7 Where is ReduceLROnPlateau used?

- Regression.
- Classification.
- Neural networks.
- Models where validation performance is monitored.
- Training tasks without a reliable fixed schedule.

# 11. Warm-Up Learning Rate

## 11.1 What is Learning Rate Warm-Up?

Warm-up means starting training with a small learning rate and gradually increasing it to a target learning rate.

This is the opposite direction from ordinary learning-rate decay.

Example:

```python
target_lr = 0.001
```

During the first few epochs:

| Epoch | Learning rate |
|---|---:|
| 1 | 0.0002 |
| 2 | 0.0004 |
| 3 | 0.0006 |
| 4 | 0.0008 |
| 5 | 0.0010 |

After warm-up, training continues using the target learning rate or another schedule.

## 11.2 Why do we use warm-up?

Some neural networks can experience unstable updates at the beginning of training, especially when using large initial learning rates.

Warm-up gradually increases the learning rate.

This can make early training more stable.

It is especially common in large Transformer training setups.

## 11.3 Python implementation

```python
target_lr = 0.001
warmup_epochs = 5

for epoch in range(100):

    if epoch < warmup_epochs:

        lr = target_lr * ((epoch + 1) / warmup_epochs)

    else:

        lr = target_lr

    # Calculate predictions
    # Calculate loss
    # Calculate gradients
    # Update weights
```

This example uses linear warm-up followed by a constant learning rate.

## 11.4 Where is Warm-Up used?

- Transformers.
- Large language models.
- Deep neural networks.
- Large-batch training.
- Some computer-vision architectures.

# 12. Cyclical Learning Rate (CLR)

## 12.1 What is Cyclical Learning Rate?

Cyclical Learning Rate changes the learning rate repeatedly between a minimum and maximum value.

Instead of only decreasing, the learning rate rises and falls in cycles.

Example:

```text
Minimum LR = 0.001
Maximum LR = 0.01
```

The schedule may behave like:

```text
0.001 → 0.003 → 0.005 → 0.008 → 0.01
0.008 → 0.005 → 0.003 → 0.001
```

Then another cycle can begin.

## 12.2 Why use it?

A changing learning rate can help a model explore different regions of the loss surface.

The goal is to avoid relying on a single fixed learning rate throughout training.

## 12.3 Python example

```python
min_lr = 0.001
max_lr = 0.01

cycle_length = 20

for epoch in range(100):

    position = epoch % cycle_length

    half_cycle = cycle_length / 2

    if position <= half_cycle:

        progress = position / half_cycle

        lr = min_lr + (max_lr - min_lr) * progress

    else:

        progress = (position - half_cycle) / half_cycle

        lr = max_lr - (max_lr - min_lr) * progress

    # Prediction
    # Calculate loss
    # Calculate gradients
    # Update weights
```

This is a simple triangular cyclical schedule.

## 12.4 Where is CLR used?

- Neural-network experiments.
- Deep learning.
- Problems where cyclical exploration is useful.
- Experiments where a fixed monotonically decreasing LR is not ideal.

---

# 13. One-Cycle Learning Rate Policy

## 13.1 What is One-Cycle?

One-Cycle is a learning-rate policy that increases the learning rate during an initial part of training and decreases it during the remaining part.

It combines:

1. Learning-rate increase.
2. Learning-rate decrease.
3. Often, a final reduction toward a very small learning rate.

It is related to cyclical learning-rate ideas, but the training schedule is designed as one overall cycle.

## 13.2 Example

Imagine:

```text
Starting LR = 0.001
Maximum LR  = 0.01
Final LR    = 0.00001
```

The training schedule:

- Beginning: LR increases.
- Middle: LR reaches its maximum.
- Remaining training: LR decreases.
- End: LR reaches a very small value.

## 13.3 Where is One-Cycle used?

- CNN training.
- Computer vision.
- Neural-network training.
- Some deep-learning tasks where training duration is known.

# 14. Comparing Learning Rate Scheduling Methods

| Method | Behaviour | Uses model performance? |
|---|---|---|
| Step Decay | Sudden fixed drops | No |
| Exponential Decay | Gradual exponential reduction | No |
| Cosine Annealing | Smooth cosine-shaped reduction | No |
| ReduceLROnPlateau | Reduces after progress stalls | Yes |
| Warm-Up | Gradually increases LR | No |
| Cyclical LR | Repeatedly rises and falls | No |
| One-Cycle | Rises once, then decreases | No |

Important:

Most scheduled methods follow a predetermined training schedule.

ReduceLROnPlateau is different because it reacts to a monitored metric.

# 15. Learning Rate Scheduling in PyTorch

In real AI/ML projects, we usually use established scheduling implementations instead of writing every schedule manually.

PyTorch provides several learning-rate schedulers.

## 15.1 StepLR

```python
import torch

optimizer = torch.optim.Adam(
    model.parameters(),
    lr=0.01
)

scheduler = torch.optim.lr_scheduler.StepLR(
    optimizer,
    step_size=50,
    gamma=0.5
)
```

Meaning:

- `step_size=50`: Reduce LR every 50 scheduler steps.
- `gamma=0.5`: Multiply LR by 0.5.

Training:

```python
for epoch in range(200):

    # Train the model
    train_model()

    # Update scheduler
    scheduler.step()
```

For StepLR, call the scheduler after the training epoch so the new rate applies to the next epoch.

## 15.2 ExponentialLR

```python
scheduler = torch.optim.lr_scheduler.ExponentialLR(
    optimizer,
    gamma=0.9
)
```

Meaning:

The learning rate is multiplied by 0.9 every scheduler step.

```python
for epoch in range(100):

    train_model()

    scheduler.step()
```

## 15.3 CosineAnnealingLR

```python
scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(
    optimizer,
    T_max=100,
    eta_min=0.0001
)
```

Meaning:

- `T_max`: Length of the cosine schedule in scheduler steps.
- `eta_min`: Minimum learning rate.

```python
for epoch in range(100):

    train_model()

    scheduler.step()
```

## 15.4 ReduceLROnPlateau

```python
scheduler = torch.optim.lr_scheduler.ReduceLROnPlateau(
    optimizer,
    mode="min",
    factor=0.5,
    patience=3,
    min_lr=0.00001
)
```

Meaning:

- `mode="min"`: Lower monitored values are better.
- `factor=0.5`: Halve the LR when triggered.
- `patience=3`: Wait for three epochs without improvement.
- `min_lr`: Do not reduce below this value.

Training:

```python
for epoch in range(100):

    train_model()

    validation_loss = evaluate_model()

    scheduler.step(validation_loss)
```

Important:

Unlike the other examples, ReduceLROnPlateau needs the monitored metric passed to `scheduler.step()`.

## 15.5 Linear Warm-Up

PyTorch provides `LinearLR`:

```python
scheduler = torch.optim.lr_scheduler.LinearLR(
    optimizer,
    start_factor=0.1,
    total_iters=5
)
```

This gradually increases the learning rate from a fraction of its initial value to the optimizer's configured learning rate over five scheduler steps.

## 15.6 OneCycleLR

```python
scheduler = torch.optim.lr_scheduler.OneCycleLR(
    optimizer,
    max_lr=0.01,
    total_steps=1000
)
```

Unlike epoch-based examples, OneCycleLR is commonly stepped after every training batch.

```python
for epoch in range(10):

    for batch in train_loader:

        # Forward pass
        # Calculate loss
        # Backward pass
        # Update parameters

        optimizer.step()

        scheduler.step()
```

Here, `total_steps` must match the total number of scheduler updates.

# 16. Learning Rate Scheduling in TensorFlow / Keras

TensorFlow and Keras also provide learning-rate scheduling.

## 16.1 Exponential Decay

```python
import tensorflow as tf

initial_lr = 0.001

lr_schedule = tf.keras.optimizers.schedules.ExponentialDecay(
    initial_learning_rate=initial_lr,
    decay_steps=1000,
    decay_rate=0.9
)

optimizer = tf.keras.optimizers.Adam(
    learning_rate=lr_schedule
)
```

The learning rate decreases according to the exponential schedule as training steps increase.

## 16.2 Cosine Decay

```python
lr_schedule = tf.keras.optimizers.schedules.CosineDecay(
    initial_learning_rate=0.001,
    decay_steps=1000,
    alpha=0.01
)

optimizer = tf.keras.optimizers.Adam(
    learning_rate=lr_schedule
)
```

`alpha` controls the final learning-rate fraction relative to the initial rate.

## 16.3 ReduceLROnPlateau

```python
callback = tf.keras.callbacks.ReduceLROnPlateau(
    monitor="val_loss",
    factor=0.5,
    patience=3,
    min_lr=0.00001
)
```

Use it during training:

```python
model.fit(
    X_train,
    y_train,
    validation_data=(X_val, y_val),
    epochs=100,
    callbacks=[callback]
)
```

The callback monitors validation loss and reduces LR when improvement stalls.

# 17. How Do We Know Whether the Learning Rate Is Working?

We should evaluate how training behaves.

Important things to observe:

1. Training loss.
2. Validation loss.
3. Learning-rate value.
4. Whether training is stable.
5. Whether validation performance improves.

## 17.1 Case A: Training loss decreases very slowly

Possible causes:

- Learning rate is too small.
- Gradients are small.
- Features are poorly scaled.
- Model is not suitable for the problem.
- Training has not run for enough iterations.

Do not immediately increase LR without investigating the other possibilities.

## 17.2 Case B: Training loss increases dramatically

Possible causes:

- Learning rate is too large.
- Gradients are exploding.
- Numerical instability.
- Incorrect gradient calculations.
- Data or preprocessing problems.

A lower LR may help if the update size is the cause.

## 17.3 Case C: Training loss decreases but validation loss increases

This may indicate overfitting.

Example:

| Epoch | Training loss | Validation loss |
|---|---:|---:|
| 1 | 100 | 110 |
| 2 | 70 | 80 |
| 3 | 40 | 55 |
| 4 | 20 | 50 |
| 5 | 10 | 65 |

The training loss keeps improving, but validation loss gets worse.

Reducing LR alone does not necessarily solve overfitting.

Other methods may be needed, such as:

- Regularization.
- Early stopping.
- More training data.
- Data augmentation where appropriate.
- A simpler model.

# 18. Practical Learning Rate Experiment Using House-Price Regression

We can compare several learning rates using your own model.

Dataset:

```python
size = [1000, 1500, 2000, 2500]

bedrooms = [2, 3, 3, 4]

age = [10, 8, 5, 2]

y = [20, 30, 40, 50]
```

The model:

```python
prediction = (
    w1 * Size +
    w2 * Bedrooms +
    w3 * Age +
    b
)
```

The loss function is Mean Squared Error.

## 18.1 Complete experiment

```python
learning_rates = [
    0.00000001,
    0.0000001,
    0.000001
]

n = len(y)

for selected_lr in learning_rates:

    # Reset weights for every experiment
    w1 = 0.0
    w2 = 0.0
    w3 = 0.0
    b = 0.0

    lr = selected_lr

    print("\nTesting LR:", lr)

    for epoch in range(1000):

        Sum_size = 0.0
        Sum_bedrooms = 0.0
        Sum_age = 0.0
        Sum_bias = 0.0

        total_loss = 0.0

        for Size, Bedrooms, Age, actual in zip(
            size, bedrooms, age, y
        ):

            # Prediction
            prediction = (
                w1 * Size +
                w2 * Bedrooms +
                w3 * Age +
                b
            )

            # Error
            error = actual - prediction

            # Accumulate gradients
            Sum_size += error * Size
            Sum_bedrooms += error * Bedrooms
            Sum_age += error * Age
            Sum_bias += error

            # Calculate squared error
            total_loss += error ** 2

        # Average gradients
        Size_grad = -(2/n) * Sum_size
        Bedrooms_grad = -(2/n) * Sum_bedrooms
        Age_grad = -(2/n) * Sum_age
        B_gradient = -(2/n) * Sum_bias

        # Update weights
        w1 -= lr * Size_grad
        w2 -= lr * Bedrooms_grad
        w3 -= lr * Age_grad
        b -= lr * B_gradient

        # Average loss from predictions
        mse = total_loss / n

        if (epoch + 1) % 100 == 0:

            print(
                "Epoch:", epoch + 1,
                "MSE:", mse
            )

    print("Final weights:", w1, w2, w3, b)
```

Important detail:

The MSE in this example is calculated before the weight update for that epoch.

The displayed final epoch's MSE therefore evaluates the weights before that epoch's update.

For a final evaluation, calculate predictions and loss again after training.

Also, the dataset has features with different scales. If a learning rate causes unstable updates, feature scaling should be investigated before assuming that the scheduler is the only issue.

# 19. Important Practical Concepts

## 19.1 Learning Rate vs Learning Rate Scheduler

These are different concepts.

Learning rate:

The value that controls the scale of parameter updates.

Learning-rate scheduler:

A method that changes the learning rate during training.

## 19.2 Learning Rate vs Number of Epochs

Learning rate controls update size.

Epochs control how many complete passes the model makes through the training dataset.

They are not interchangeable.

## 19.3 Learning Rate vs Batch Size

Batch size determines how many training samples are used to calculate a gradient update.

Learning rate determines the scale of the resulting parameter update.

Changing batch size can affect which learning rate works well, but they control different things.

## 19.4 Learning Rate vs Gradient

Gradient describes how the loss changes with respect to a parameter.

Learning rate controls how strongly the optimizer uses that gradient to update the parameter.

# 20. Which Learning Rate Method Should We Use?

There is no universal best method.

A practical starting guide:

| Situation | Method to try |
|---|---|
| Simple fixed training schedule | Step Decay |
| Smooth reduction | Exponential Decay |
| Smooth planned reduction | Cosine Annealing |
| Validation loss stops improving | ReduceLROnPlateau |
| Unstable early training | Warm-Up |
| Experimenting with repeated LR changes | Cyclical LR |
| Training with one planned LR cycle | One-Cycle |

For many modern neural networks, warm-up followed by cosine decay is a common strategy.

For simpler experiments, a fixed learning rate or ReduceLROnPlateau can be a useful starting point.

The correct choice should be validated on the actual task.

# 21. Final Summary

Learning Rate is one of the most important training settings in gradient-based machine learning.

It controls the size of parameter updates.

The main concepts are:

1. Learning rate controls update size.
2. Gradients also determine the size and direction of updates.
3. Very small LR can make training slow.
4. Very large LR can make training unstable.
5. Feature scaling can strongly affect suitable LR values.
6. A Learning Rate Finder can help identify a starting value.
7. Learning Rate Scheduling changes LR during training.

Important scheduling methods:

- Step Decay: Fixed interval reductions.
- Exponential Decay: Exponential reduction.
- Cosine Annealing: Cosine-shaped reduction.
- ReduceLROnPlateau: Reduction when progress stalls.
- Warm-Up: Gradual increase at the beginning.
- Cyclical LR: Repeated increase and decrease.
- One-Cycle: One planned increase followed by a decrease.

For practical AI/ML work, you should understand both the mathematics and how to implement these methods in PyTorch or TensorFlow.

The objective is not to memorize every scheduler.

The objective is to understand why a learning-rate strategy is selected, how it changes training, and whether it improves validation performance.
