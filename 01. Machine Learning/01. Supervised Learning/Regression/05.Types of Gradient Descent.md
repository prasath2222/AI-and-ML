
# Types of Gradient Descent

# 1. Introduction

Gradient Descent is an optimization algorithm used to train machine learning models.

Its purpose is to find suitable model parameters (weights and bias) that minimize the loss function.

During training, Gradient Descent repeatedly:

1. Takes training data.
2. Calculates predictions.
3. Calculates prediction errors.
4. Calculates loss.
5. Calculates gradients.
6. Updates weights and bias.
7. Repeats the process.

There are three main ways to use training data when calculating gradients and updating model parameters:

1. Batch Gradient Descent
2. Stochastic Gradient Descent (SGD)
3. Mini-Batch Gradient Descent

The main difference between these three methods is:

**How many training examples are used to calculate a gradient before updating the model's parameters?**

---

# Batch Gradient Descent – NumPy Implementation

## 1. Import NumPy

```python
import numpy as np
```

## 2. Dataset

```python
X = np.array([1, 2, 3, 6])
Y = np.array([5, 10, 9, 16])
N = len(X)
```

## 3. Initialize Parameters

```python
w = 0.0
b = 0.0
lr = 0.02
```

## 4. Training Loop

```python
for epoch in range(1000):

    # Process all rows together
    guesses = (w * X) + b

    misses = Y - guesses

    # Calculate overall gradients
    sum_miss = np.sum(misses)
    sum_x_miss = np.sum(X * misses)

    w_grad = -(2 / N) * sum_x_miss
    b_grad = -(2 / N) * sum_miss

    # Calculate MSE
    mse = np.mean(misses ** 2)

    # Update weight and bias
    w = w - (lr * w_grad)
    b = b - (lr * b_grad)
```

## 5. Display Final Results

```python
print("Weight:", w)
print("Bias:", b)
print("MSE:", mse)
```

## 6. Predict on New Input

```python
new_x = 5

prediction = (w * new_x) + b

print("Prediction:", prediction)
```

## Key Concepts

- One outer loop for all epochs.
- NumPy processes all dataset rows together.
- Gradients are calculated using all rows.
- Weight and bias are updated once per epoch.
- This is Batch Gradient Descent.

# PART 1: BATCH GRADIENT DESCENT

# 3. What Is Batch Gradient Descent?

Batch Gradient Descent uses the entire training dataset to calculate gradients before updating model parameters.

It does not update weights after processing each individual training example.

Instead, it:

1. Processes every training example.
2. Calculates every prediction.
3. Calculates every error.
4. Combines information from all examples.
5. Calculates the overall gradients.
6. Updates weights and bias once.

### Example

Our dataset contains four houses.

Batch Gradient Descent processes all four houses before updating the weights.

```text
House 1 → Prediction → Error
House 2 → Prediction → Error
House 3 → Prediction → Error
House 4 → Prediction → Error

          ↓

Combine information from all four houses

          ↓

Calculate gradients

          ↓

Update weights and bias ONCE
```

### Important

For four training examples:

- Training examples processed = 4
- Predictions calculated = 4
- Errors calculated = 4
- Combined gradient calculation = 1 per parameter
- Weight updates = 1 per epoch

---

# 4. How Batch Gradient Descent Works

Let's understand the complete process.

### Step 1: Initialize weights and bias

```python
w1 = 0.0
w2 = 0.0
w3 = 0.0

b = 0.0

lr = 0.0000001
```

Initially, all weights and bias are zero.

### Step 2: Process the entire dataset

We calculate predictions and errors for all four houses.

```python
for Size, Bedrooms, Age, actual in zip(
    size, bedrooms, age, y
):

    prediction = (
        w1 * Size +
        w2 * Bedrooms +
        w3 * Age +
        b
    )

    error = actual - prediction
```

The model processes all four training examples.

### Step 3: Accumulate gradient information

We maintain separate accumulated values for each parameter.

```python
sum_size_blame = 0.0
sum_bedrooms_blame = 0.0
sum_age_blame = 0.0
sum_overall_blame = 0.0
```

For each training example:

```python
sum_size_blame += error * Size

sum_bedrooms_blame += error * Bedrooms

sum_age_blame += error * Age

sum_overall_blame += error
```

Each training example contributes to the accumulated gradient information.

### Step 4: Calculate combined gradients

After processing all four houses:

```python
size_grad = -(2 / n) * sum_size_blame

bedrooms_grad = -(2 / n) * sum_bedrooms_blame

age_grad = -(2 / n) * sum_age_blame

b_gradient = -(2 / n) * sum_overall_blame
```

Here, `n = 4` because the entire dataset contains four training examples.

### Step 5: Update weights

Now update all parameters once.

```python
w1 = w1 - (lr * size_grad)

w2 = w2 - (lr * bedrooms_grad)

w3 = w3 - (lr * age_grad)

b = b - (lr * b_gradient)
```

One complete dataset pass produces one update of each parameter.

---

# 5. Batch Gradient Descent: Complete Python Implementation

```python
# Dataset

size = [1000, 1500, 2000, 2500]

bedrooms = [2, 3, 3, 4]

age = [10, 8, 5, 2]

y = [20, 30, 40, 50]

n = len(y)


# Initialize parameters

w1 = 0.0
w2 = 0.0
w3 = 0.0

b = 0.0

lr = 0.0000001


# Training

for epoch in range(1000):

    # Reset accumulated values

    sum_size_blame = 0.0
    sum_bedrooms_blame = 0.0
    sum_age_blame = 0.0
    sum_overall_blame = 0.0

    total_loss = 0.0

    # Process the entire dataset

    for Size, Bedrooms, Age, actual in zip(
        size, bedrooms, age, y
    ):

        prediction = (
            w1 * Size +
            w2 * Bedrooms +
            w3 * Age +
            b
        )

        error = actual - prediction

        total_loss += error ** 2

        sum_size_blame += error * Size

        sum_bedrooms_blame += error * Bedrooms

        sum_age_blame += error * Age

        sum_overall_blame += error


    # Calculate overall MSE

    loss = total_loss / n


    # Calculate gradients

    size_grad = -(2 / n) * sum_size_blame

    bedrooms_grad = -(2 / n) * sum_bedrooms_blame

    age_grad = -(2 / n) * sum_age_blame

    b_gradient = -(2 / n) * sum_overall_blame


    # Update weights once per epoch

    w1 = w1 - (lr * size_grad)

    w2 = w2 - (lr * bedrooms_grad)

    w3 = w3 - (lr * age_grad)

    b = b - (lr * b_gradient)


    print(f"Epoch {epoch + 1}, Loss: {loss:.4f}")
```

### Important observations

The weights are updated outside the inner loop.

This is important.

If we update weights inside the inner loop, we are no longer performing ordinary Batch Gradient Descent.

### Advantages

1. Uses the entire training dataset to calculate each update.
2. Generally produces less noisy gradient estimates.
3. Provides relatively smooth optimization behaviour for a fixed learning rate.
4. Simple to understand and implement.
5. Useful for smaller datasets.

### Disadvantages

1. Requires processing the entire dataset before each update.
2. Large datasets can require substantial memory and computation.
3. Produces only one update per epoch.
4. Can be slow when the dataset is extremely large.
5. Does not take advantage of frequent updates from individual examples.

### When is it useful?

Batch Gradient Descent can be useful when:

- The dataset is small.
- The entire dataset fits comfortably in memory.
- A stable full-dataset gradient is desired.
- The optimization problem is relatively simple.

# PART 2: STOCHASTIC GRADIENT DESCENT

# 6. What Is Stochastic Gradient Descent?

Stochastic Gradient Descent (SGD) uses one training example at a time to calculate a gradient and update model parameters.

Unlike Batch Gradient Descent, SGD does not wait for the entire dataset.

It performs an update after processing each individual training example.

### Example

Our dataset contains four houses.

SGD works like this:

```text
House 1
   ↓
Calculate prediction
   ↓
Calculate error
   ↓
Calculate gradient
   ↓
Update weights

House 2
   ↓
Calculate prediction
   ↓
Calculate error
   ↓
Calculate gradient
   ↓
Update weights

House 3
   ↓
Calculate prediction
   ↓
Calculate error
   ↓
Calculate gradient
   ↓
Update weights

House 4
   ↓
Calculate prediction
   ↓
Calculate error
   ↓
Calculate gradient
   ↓
Update weights
```

### Important

For four training examples:

- Training examples processed = 4
- Weight updates = 4 per epoch

One example produces one parameter update.

---

# 7. How Stochastic Gradient Descent Works

### Step 1: Initialize weights

```python
w1 = 0.0
w2 = 0.0
w3 = 0.0

b = 0.0

lr = 0.0000001
```

### Step 2: Process one training example

```python
for Size, Bedrooms, Age, actual in zip(
    size, bedrooms, age, y
):
```

The loop processes one house at a time.

### Step 3: Calculate prediction

```python
prediction = (
    w1 * Size +
    w2 * Bedrooms +
    w3 * Age +
    b
)
```

### Step 4: Calculate error

```python
error = actual - prediction
```

### Step 5: Calculate gradients using that one example

```python
size_grad = -2 * error * Size

bedrooms_grad = -2 * error * Bedrooms

age_grad = -2 * error * Age

b_gradient = -2 * error
```

There is no division by the total dataset size because this update uses only one training example.

### Step 6: Update weights immediately

```python
w1 = w1 - (lr * size_grad)

w2 = w2 - (lr * bedrooms_grad)

w3 = w3 - (lr * age_grad)

b = b - (lr * b_gradient)
```

The model updates its weights before moving to the next house.

### Important detail

House 2 uses the weights updated after House 1.

House 3 uses the weights updated after House 2.

House 4 uses the weights updated after House 3.

This is the essential behaviour of SGD.

---

# 8. Stochastic Gradient Descent: Complete Python Implementation

```python
# Dataset

size = [1000, 1500, 2000, 2500]

bedrooms = [2, 3, 3, 4]

age = [10, 8, 5, 2]

y = [20, 30, 40, 50]


# Initialize parameters

w1 = 0.0
w2 = 0.0
w3 = 0.0

b = 0.0

lr = 0.0000001


# Training

for epoch in range(1000):

    total_loss = 0.0

    for Size, Bedrooms, Age, actual in zip(
        size, bedrooms, age, y
    ):

        # Prediction

        prediction = (
            w1 * Size +
            w2 * Bedrooms +
            w3 * Age +
            b
        )

        # Error

        error = actual - prediction

        # Record squared error

        total_loss += error ** 2

        # Calculate gradients using one example

        size_grad = -2 * error * Size

        bedrooms_grad = -2 * error * Bedrooms

        age_grad = -2 * error * Age

        b_gradient = -2 * error

        # Update weights immediately

        w1 = w1 - (lr * size_grad)

        w2 = w2 - (lr * bedrooms_grad)

        w3 = w3 - (lr * age_grad)

        b = b - (lr * b_gradient)


    # Average loss across the dataset

    loss = total_loss / len(y)

    print(f"Epoch {epoch + 1}, Loss: {loss:.4f}")
```

### Important observation

In this example, loss is recorded before each individual update.

Therefore, the printed loss is an average of the squared errors observed while processing the dataset with changing parameters.

It is not exactly the same as evaluating the final updated model on all four houses after the epoch.

For a fair comparison of final model performance, calculate the loss separately after the epoch using the final weights.

### Advantages

1. Updates parameters frequently.
2. Does not need the entire dataset for each update.
3. Can begin learning immediately.
4. Useful for very large or streaming datasets.
5. Individual updates can help move through complicated optimization landscapes.

### Disadvantages

1. Updates can be noisy.
2. Loss may fluctuate significantly.
3. Can be sensitive to the learning rate.
4. May not settle smoothly near a minimum.
5. Requires careful monitoring of training behaviour.

### When is it useful?

SGD can be useful when:

- Data arrives continuously.
- Individual updates are desirable.
- The dataset is extremely large.
- Memory limitations make full-batch processing impractical.

---

# 9. Why Does SGD Produce Noisy Updates?

This is one of the most important concepts.

Every training example can produce a different gradient.

Imagine four individual gradients for one parameter:

| House | Gradient |
|---|---:|
| 1 | 10 |
| 2 | -5 |
| 3 | 20 |
| 4 | -10 |

SGD processes them separately.

Its updates are influenced by:

- Gradient 10
- Gradient -5
- Gradient 20
- Gradient -10

The gradient can change in magnitude and direction from one example to another.

This produces fluctuations in parameter updates.

This behaviour is called gradient noise.

### Why do individual examples produce different gradients?

Because the examples have different:

- Input features.
- Actual target values.
- Prediction errors.
- Contributions to the overall loss.

One house may suggest increasing a particular weight, while another house may suggest decreasing it.

SGD responds to each example separately.

### Important

Noisy does not mean incorrect.

It means an individual gradient is only an estimate of the overall dataset gradient.

# PART 3: MINI-BATCH GRADIENT DESCENT

# 10. What Is Mini-Batch Gradient Descent?

Mini-Batch Gradient Descent divides the training dataset into smaller groups called mini-batches.

It calculates gradients using one mini-batch and updates model parameters once per mini-batch.

It combines characteristics of Batch Gradient Descent and SGD.

- Batch GD uses the entire dataset per update.
- SGD uses one example per update.
- Mini-Batch GD uses a small group per update.

### Example

Suppose we have four houses:

| House | Actual price |
|---|---:|
| 1 | 20 |
| 2 | 30 |
| 3 | 40 |
| 4 | 50 |

Choose:

```python
batch_size = 2
```

We divide the dataset into two groups.

```text
Batch 1:
House 1
House 2

       ↓

Calculate combined gradient

       ↓

Update weights once


Batch 2:
House 3
House 4

       ↓

Calculate combined gradient

       ↓

Update weights once
```

### Important

For four houses and batch size two:

- Total training examples = 4
- Batch size = 2
- Number of batches = 2
- Weight updates per epoch = 2

---

# 11. What Is Batch Size?

Batch size is the number of training examples processed together before one weight update.

Example:

```python
batch_size = 2
```

This means the model processes two training examples before updating its weights.

### Different batch sizes

Suppose the dataset contains 1,000 training examples.

| Batch size | Meaning | Updates per epoch |
|---:|---|---:|
| 1 | One example per update | 1,000 |
| 10 | Ten examples per update | 100 |
| 32 | Thirty-two per update | 32 |
| 100 | One hundred per update | 10 |
| 1000 | Entire dataset per update | 1 |

The number of updates assumes the final incomplete batch is kept where necessary.

### Important relationship

For a fixed dataset:

- Smaller batch size = More updates per epoch.
- Larger batch size = Fewer updates per epoch.

Let's implement it step by step.

```python
size = [1000, 1500, 2000, 2500]

bedrooms = [2, 3, 3, 4]

age = [10, 8, 5, 2]
```

```python
w1 = 0.0
```

```python
for start in range(0, len(size), batch_size):
```

```python
batch_size_data = [1000, 1500]
```

```python
batch_size_data = [2000, 2500]

```

We must not accidentally carry the previous batch's accumulated gradients into the next batch.

```python
for Size, Bedrooms, Age, actual in zip(
```

```python
sum_size_blame += error * Size

sum_bedrooms_blame += error * Bedrooms

sum_age_blame += error * Age

sum_overall_blame += error
```

```python
current_batch_size = len(batch_y)

bedrooms_grad = -(2 / current_batch_size) * sum_bedrooms_blame

age_grad = -(2 / current_batch_size) * sum_age_blame

b_gradient = -(2 / current_batch_size) * sum_overall_blame
```

We divide by the current batch size, not the entire dataset size.

### Step 8: Update parameters once

```python
w1 = w1 - (lr * size_grad)

w2 = w2 - (lr * bedrooms_grad)

w3 = w3 - (lr * age_grad)

b = b - (lr * b_gradient)
```

Now the model moves to the next batch.

The next batch uses the newly updated parameters.

# 13. Complete Mini-Batch Gradient Descent Implementation

```python
# Dataset

size = [1000, 1500, 2000, 2500]

bedrooms = [2, 3, 3, 4]

age = [10, 8, 5, 2]

y = [20, 30, 40, 50]


# Dataset size

n = len(y)


# Training settings

batch_size = 2

epochs = 1000

lr = 0.0000001


# Initialize parameters

w1 = 0.0
w2 = 0.0
w3 = 0.0

b = 0.0


# Training

for epoch in range(epochs):

    total_squared_error = 0.0

    # Move through dataset batch by batch

    for start in range(0, n, batch_size):

        end = start + batch_size

        # Extract batch

        batch_size_data = size[start:end]

        batch_bedrooms = bedrooms[start:end]

        batch_age = age[start:end]

        batch_y = y[start:end]


        # Reset accumulators for this batch

        sum_size_blame = 0.0

        sum_bedrooms_blame = 0.0

        sum_age_blame = 0.0

        sum_overall_blame = 0.0


        # Process examples in current batch

        for Size, Bedrooms, Age, actual in zip(
            batch_size_data,
            batch_bedrooms,
            batch_age,
            batch_y
        ):

            # Prediction

            prediction = (
                w1 * Size +
                w2 * Bedrooms +
                w3 * Age +
                b
            )

            # Error

            error = actual - prediction

            # Accumulate squared error

            total_squared_error += error ** 2

            # Accumulate gradient information

            sum_size_blame += error * Size

            sum_bedrooms_blame += error * Bedrooms

            sum_age_blame += error * Age

            sum_overall_blame += error


        # Actual number of examples in this batch

        current_batch_size = len(batch_y)


        # Calculate batch gradients

        size_grad = -(2 / current_batch_size) * sum_size_blame

        bedrooms_grad = -(2 / current_batch_size) * sum_bedrooms_blame

        age_grad = -(2 / current_batch_size) * sum_age_blame

        b_gradient = -(2 / current_batch_size) * sum_overall_blame


        # Update parameters once per batch

        w1 = w1 - (lr * size_grad)

        w2 = w2 - (lr * bedrooms_grad)

        w3 = w3 - (lr * age_grad)

        b = b - (lr * b_gradient)


    # Calculate average squared error observed during this epoch

    epoch_loss = total_squared_error / n

    print(f"Epoch {epoch + 1}, Loss: {epoch_loss:.4f}")


print("Final weights:")

print("w1:", w1)

print("w2:", w2)

print("w3:", w3)

print("b:", b)
```

### Important implementation detail

The loss in this particular example is accumulated while the model is processing batches whose weights are changing.

It is useful as a record of training errors, but it is not exactly the loss of the final model at the end of the epoch.

For accurate epoch-end evaluation, run a separate prediction pass using the final weights after all batches have been processed.

# 15. Gradient Noise and Gradient Variance

To understand why these methods behave differently, we need to understand gradient noise.

### What is a gradient?

A gradient measures how the loss changes with respect to model parameters.

It tells the optimization algorithm how to adjust the parameters.

### What is gradient noise?

A gradient calculated from only one or a small number of training examples may differ from the gradient calculated using the entire dataset.

This difference is called gradient noise.

### What is gradient variance?

Variance describes how much individual gradient estimates differ from one another.

For example:

Imagine different mini-batches produce these gradients:

```text
Batch 1: 10
Batch 2: 12
Batch 3: 8
Batch 4: 11
```

The gradients are relatively close.

Now imagine:

```text
Batch 1: 50
Batch 2: -20
Batch 3: 80
Batch 4: -40
```

The gradients vary much more.

The second situation has greater variation in gradient estimates.

### How batch size affects gradient variance

Generally, when examples are sampled independently and gradients have finite variance:

- Smaller batches produce noisier gradient estimates.
- Larger batches produce less noisy gradient estimates.

The exact behaviour also depends on the dataset and how examples are sampled.

### Why is this important?

Noisy gradients can cause:

1. More fluctuations in parameter updates.
2. More fluctuations in training loss.
3. Less direct movement toward a minimum.
4. More difficulty choosing a learning rate.

However, gradient noise is not always harmful. It can sometimes help optimization explore complicated loss landscapes.

# 16. Batch Size and Learning Rate

Batch size and learning rate are two different training settings.

### Batch size

Controls how many training examples contribute to one gradient update.

### Learning rate

Controls the size of the parameter update.

Example:

```python
batch_size = 32

lr = 0.001
```

Here:

- `batch_size = 32` means 32 examples contribute to each update.
- `lr = 0.001` controls how strongly the parameters are changed.

### Why do they interact?

Changing the batch size changes the variability of gradient estimates.

A smaller batch may produce noisier updates.

A larger batch may produce more stable gradient estimates.

Therefore, the learning rate may need to be adjusted when changing batch size.

There is no universal rule that one learning rate works for every batch size.

Batch size and learning rate should be tested together.

# 17. Small Batch Size vs Large Batch Size

### Small batch size

Example:

```python
batch_size = 8
```

Characteristics:

- More batches per epoch.
- More weight updates per epoch.
- Noisier gradient estimates in many situations.
- Lower memory requirement per batch.
- Can be less efficient on some hardware.

### Large batch size

Example:

```python
batch_size = 512
```

Characteristics:

- Fewer batches per epoch.
- Fewer weight updates per epoch.
- Generally less noisy gradient estimates.
- Higher memory requirement per batch.
- Can make better use of parallel hardware.

### Comparison

| Property | Small batch | Large batch |
|---|---|---|
| Updates per epoch | More | Fewer |
| Gradient noise | Generally higher | Generally lower |
| Memory per batch | Lower | Higher |
| Parallel processing | Depends on hardware | Often more efficient |
| Learning-rate selection | Needs tuning | Needs tuning |

Neither small nor large batch size is automatically best.

# 18. Batch Size and GPU Utilization

Modern GPUs can perform many numerical operations in parallel.

Mini-batches allow the GPU to process multiple training examples together.

For example:

```python
batch_size = 32
```

The model processes 32 examples together.

A larger batch can sometimes improve GPU utilization because more parallel computation is available.

However:

- Larger batches need more GPU memory.
- Extremely large batches may exceed available memory.
- Performance depends on the model architecture and hardware.
- Larger batches do not guarantee faster total training.

The best batch size is determined through practical testing.

# PART 5: BATCHES, EPOCHS AND ITERATIONS

# 19. What Is an Epoch?

An epoch is one complete pass through the training dataset.

Suppose there are 100 training examples.

After the model has processed all 100 examples once, one epoch is complete.

### Example

```python
epochs = 10
```

This means the training dataset will be processed ten times, assuming training completes all epochs.

An epoch is not the same as one weight update.

The number of updates depends on the batch size and Gradient Descent method.

---

# 20. What Is a Batch?

A batch is a group of training examples processed together.

Example:

```python
batch_size = 10
```

The model processes ten examples before calculating and applying one combined gradient update.

---

# 21. What Is an Iteration?

An iteration is one training step in which a batch is processed and the model parameters are updated.

In ordinary mini-batch training:

One batch processed = One iteration = One optimizer update.

For example:

- Process Batch 1 → Iteration 1.
- Process Batch 2 → Iteration 2.
- Process Batch 3 → Iteration 3.

---

# 22. Calculating the Number of Batches

When the final incomplete batch is kept:

Number of batches = Ceiling of (Dataset size / Batch size)

Example:

```python
dataset_size = 103

batch_size = 10
```

There are ten complete batches and one incomplete batch.

Total batches = 11.

Python:

```python
import math

number_of_batches = math.ceil(
    dataset_size / batch_size
)

print(number_of_batches)
```

Output:

```text
11
```

When the final incomplete batch is dropped:

Number of batches = Floor of (Dataset size / Batch size)

Python:

```python
number_of_batches = dataset_size // batch_size
```

Output:

```text
10
```

---

# 23. Calculating Total Weight Updates

For ordinary mini-batch training:

Total updates = Batches per epoch × Number of epochs

Example:

```python
dataset_size = 1000

batch_size = 100

epochs = 20
```

Batches per epoch:

```text
1000 / 100 = 10
```

Total updates:

```text
10 × 20 = 200
```

The model performs 200 parameter updates across the 20 epochs.

### Important

This calculation assumes:

- One update per batch.
- The batch configuration remains unchanged.
- No early stopping.
- Every specified epoch completes.

# PART 6: INCOMPLETE BATCHES

# 24. What Is an Incomplete Batch?

An incomplete batch occurs when the dataset size cannot be divided evenly by the batch size.

Example:

```python
dataset_size = 103

batch_size = 10
```

The first ten batches contain ten examples each.

The last batch contains three examples.

| Batch | Examples |
|---|---:|
| 1 | 10 |
| 2 | 10 |
| 3 | 10 |
| 4 | 10 |
| 5 | 10 |
| 6 | 10 |
| 7 | 10 |
| 8 | 10 |
| 9 | 10 |
| 10 | 10 |
| 11 | 3 |

There are eleven batches if the incomplete batch is kept.

---

# 25. What Is drop_last?

In PyTorch DataLoader, `drop_last` controls whether the final incomplete batch is kept or discarded.

### Keep the incomplete batch

```python
drop_last = False
```

All examples are included.

For 103 examples and batch size 10:

Total batches = 11.

### Drop the incomplete batch

```python
drop_last = True
```

The final three examples are discarded for that epoch.

Total batches = 10.

### When is drop_last useful?

Keeping the incomplete batch:

- Preserves all training examples.
- Is a common default choice.

Dropping the incomplete batch:

- Makes all batches the same size.
- Can be useful when an operation requires fixed batch dimensions.
- Discards some examples during that epoch.

Dropping the final batch is not automatically better.

# PART 7: SHUFFLING

# 26. What Is Shuffling?

Shuffling means randomly changing the order of training examples.

Suppose the original dataset is:

```text
H1, H2, H3, H4, H5, H6
```

After shuffling:

```text
H4, H1, H6, H2, H5, H3
```

The examples are the same.

Only their order has changed.

---

# 27. Why Do We Shuffle?

Imagine the dataset is sorted by house price.

```text
Low-price houses
Low-price houses
Low-price houses
Medium-price houses
Medium-price houses
High-price houses
High-price houses
High-price houses
```

If we always divide this dataset into batches in the same order, some batches may contain only similar examples.

Shuffling can mix different kinds of examples.

Benefits:

1. Reduces unwanted patterns caused by the original ordering.
2. Creates different mini-batch combinations across epochs.
3. Can improve the behaviour of stochastic and mini-batch training.
4. Helps avoid repeatedly processing the same groups in the same order.

### Important

Shuffling changes the order of examples, not their values.

Input features and targets must always stay together.

---

# 28. Shuffling in Python

```python
import random

size = [1000, 1500, 2000, 2500]

y = [20, 30, 40, 50]

# Combine matching input and target values

dataset = list(zip(size, y))

# Shuffle complete examples

random.shuffle(dataset)

print(dataset)
```

Possible output:

```text
[(2000, 40), (1000, 20), (2500, 50), (1500, 30)]
```

The matching prices remain attached to their corresponding house sizes.

### Why not shuffle each list separately?

This is incorrect:

```python
random.shuffle(size)

random.shuffle(y)
```

The two lists may end up in different orders.

That can match a house size with the wrong actual price.

Always shuffle complete examples together.

---

# 29. Reproducibility and Random Seeds

Shuffling is random.

This means different training runs can use different example orders.

A random seed helps make the random process repeatable.

Example:

```python
import random

random.seed(42)

random.shuffle(dataset)
```

Using the same seed and the same initial dataset allows the same shuffle sequence to be reproduced in the same environment.

Reproducibility is important when:

- Comparing experiments.
- Debugging training.
- Recording model results.
- Repeating research experiments.

For complete reproducibility in machine learning, other sources of randomness and hardware-related behaviour may also need to be controlled.

---

# 30. Shuffling in Time-Series Datasets

This is especially important for financial and cryptocurrency prediction.

Time-series data contains observations arranged in chronological order.

Example:

| Candle | Time |
|---|---|
| 1 | 08:00 |
| 2 | 12:00 |
| 3 | 16:00 |
| 4 | 20:00 |

Future observations must not leak into the past.

### Incorrect approach

Randomly dividing the complete time-series dataset into training and test sets can cause future observations to enter the training set while earlier observations enter the test set.

This can create data leakage and unrealistic evaluation.

### Better approach

Preserve chronological order when splitting the dataset.

For example:

```text
Earlier observations
       ↓
Training data

Later observations
       ↓
Validation data

Newest observations
       ↓
Test data
```

### Can we shuffle time-series training examples?

It depends on the model and training design.

For independent, already-created training windows, shuffling the training windows may be acceptable in some setups.

However:

- Preserve chronological train/validation/test splits.
- Never use future information to predict the past.
- Maintain temporal order inside each input sequence.
- Be especially careful with recurrent models and stateful training.

# PART 10: PYTORCH TRAINING LOOP

# 36. Understanding a PyTorch Mini-Batch Training Loop

A typical PyTorch training loop contains these important operations:

1. Get a batch.
2. Calculate predictions.
3. Calculate loss.
4. Clear old gradients.
5. Calculate new gradients using backpropagation.
6. Update model parameters.

Example:

```python
for epoch in range(epochs):

    for batch_x, batch_y in loader:

        # Calculate predictions

        predictions = model(batch_x)

        # Calculate loss

        loss = loss_function(
            predictions,
            batch_y
        )

        # Clear old gradients

        optimizer.zero_grad()

        # Calculate gradients

        loss.backward()

        # Update parameters

        optimizer.step()
```

Let's understand each operation.

---

# 37. optimizer.zero_grad()

```python
optimizer.zero_grad()
```

PyTorch accumulates gradients by default.

This means gradients from previous backward passes can remain stored.

Before calculating the next batch's gradients, we normally clear the old gradients.

`optimizer.zero_grad()` performs this operation.

Without clearing old gradients when appropriate, gradients from multiple batches may accidentally accumulate.

---

# 38. loss.backward()

```python
loss.backward()
```

This calculates gradients using automatic differentiation.

PyTorch tracks the mathematical operations used to calculate the loss.

It then calculates how the loss changes with respect to model parameters.

This is called backpropagation.

The resulting gradients are stored in each parameter's `.grad` attribute.

---

# 39. optimizer.step()

```python
optimizer.step()
```

This updates the model parameters using the gradients.

The exact update depends on the optimizer.

For example, with ordinary SGD:

```python
optimizer = torch.optim.SGD(
    model.parameters(),
    lr=0.001
)
```

The optimizer uses the calculated gradients and learning rate to update the parameters.

### Important

These three operations have different responsibilities:

| Operation | Responsibility |
|---|---|
| `zero_grad()` | Clear previous gradients |
| `backward()` | Calculate new gradients |
| `step()` | Update parameters |

---

# 40. Complete PyTorch Mini-Batch Training Example

```python
import torch

import torch.nn as nn

from torch.utils.data import TensorDataset, DataLoader


# Training data

size = torch.tensor([
    [1000.0],
    [1500.0],
    [2000.0],
    [2500.0]
])

price = torch.tensor([
    [20.0],
    [30.0],
    [40.0],
    [50.0]
])


# Create dataset

dataset = TensorDataset(size, price)


# Create DataLoader

loader = DataLoader(
    dataset,
    batch_size=2,
    shuffle=True
)


# Create model

model = nn.Linear(1, 1)


# Loss function

loss_function = nn.MSELoss()


# Optimizer

optimizer = torch.optim.SGD(
    model.parameters(),
    lr=0.00001
)


# Training settings

epochs = 100


# Training loop

for epoch in range(epochs):

    total_loss = 0.0

    for batch_x, batch_y in loader:

        # Prediction

        predictions = model(batch_x)

        # Calculate loss

        loss = loss_function(
            predictions,
            batch_y
        )

        # Clear previous gradients

        optimizer.zero_grad()

        # Calculate gradients

        loss.backward()

        # Update parameters

        optimizer.step()

        total_loss += loss.item() * len(batch_x)


    # Average observed batch loss

    epoch_loss = total_loss / len(dataset)

    print(
        f"Epoch {epoch + 1}, Loss: {epoch_loss:.4f}"
    )
```

### Important notes

1. `nn.Linear(1, 1)` creates a model with one input feature and one output.
2. This example uses house size as its only input.
3. `DataLoader` creates batches containing two houses.
4. `MSELoss` calculates Mean Squared Error.
5. `backward()` calculates gradients.
6. `optimizer.step()` updates the model parameters.

The reported epoch loss is an average of batch losses observed while parameters are changing. To evaluate the final model at the end of an epoch, run a separate evaluation pass.

Also, the learning rate must be selected appropriately for the numerical scale of the input features.

# PART 11: ADVANCED COMPARISONS

# 41. Batch Size and Generalization

Generalization means a trained model can make useful predictions on previously unseen data.

Batch size can influence optimization and sometimes generalization.

However, batch size alone does not determine whether a model generalizes well.

Generalization also depends on:

- Dataset quality.
- Model complexity.
- Training duration.
- Learning rate.
- Regularization.
- Data distribution.
- Training and validation procedures.

A model trained with a small batch is not automatically better than a model trained with a large batch.

The results must be evaluated on unseen data.

---

# 42. Batch Size and Convergence

Batch size can affect the way Gradient Descent approaches a solution.

### Small batches

- More frequent parameter updates.
- Noisier gradient estimates.
- More variation in the loss curve.

### Large batches

- Fewer parameter updates per epoch.
- Less noisy gradient estimates in typical independent sampling settings.
- Potentially smoother optimization behaviour.

The learning rate also affects convergence.

A suitable batch size with an unsuitable learning rate can still produce poor training behaviour.

Therefore, both settings should be considered together.

---

# 43. Batch Size Selection Strategies

There is no universally best batch size.

Common experimental choices include:

```python
batch_sizes = [16, 32, 64, 128, 256]
```

The process:

1. Select a reasonable starting batch size.
2. Train the model.
3. Monitor training and validation loss.
4. Check memory consumption.
5. Measure training speed.
6. Compare model performance.
7. Select a suitable batch size.

The correct choice depends on the model, dataset, hardware and training objective.

# 44. Common Mistakes

### Mistake 1: Updating weights after every example in Batch GD

This changes the algorithm from Batch Gradient Descent to SGD.

### Mistake 2: Using the entire dataset size for a mini-batch gradient

For an ordinary mini-batch mean loss, divide by the current batch size.

### Mistake 3: Forgetting to reset gradient accumulators

Each batch must start with fresh accumulators when manually calculating batch gradients.

### Mistake 4: Updating weights before completing the batch

In mini-batch training, calculate the combined gradient from the entire current batch before updating parameters.

### Mistake 5: Forgetting to keep input features and targets aligned

Shuffling feature lists independently can create incorrect training examples.

### Mistake 6: Confusing epochs with iterations

One epoch may contain many iterations.

### Mistake 7: Assuming a larger batch is always better

A larger batch is not automatically faster or more accurate.

### Mistake 8: Randomly splitting time-series data

This can introduce future information into training and create data leakage.

### Mistake 9: Forgetting to clear PyTorch gradients

Old gradients can accumulate if `optimizer.zero_grad()` is omitted when a fresh batch gradient is intended.

### Mistake 10: Assuming DataLoader trains the model

DataLoader only provides batches. The training loop performs learning.
